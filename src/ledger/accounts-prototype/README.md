问题：在现有 LifeSpace 财务页中，账户列表如何与流水共存，账户修改和转账入口是否方便使用？

使用者已选择 **A：账户平铺**，账户卡片在上、流水表格在下。本原型已固定 A 布局，移除候选布局及方案切换控件，继续继承现有财务页的视觉风格。

完整 A／B／C 候选原型已保存在本地分支 `codex/118-financial-accounts-prototype`，提交 `08a7d9e53df2ba91869b757fb6d361370990c8dc`；B、C 截图仅保留为比较记录。用户已确认实施，规格与原型来源已同步至 [#118](https://github.com/PancrasDuan/lifespace/issues/118)，任务标记为 `ready-for-agent`。

## 在归档分支运行

以下命令在上述原型归档分支执行。正式集成分支只保存设计决定、说明与截图，不接入原型运行命令；本地已启动的 5187 预览继续用于设计核对。

```bash
npm run prototype:accounts
```

打开 <http://127.0.0.1:5187/finance/accounts-prototype>。旧的带 `variant` 参数链接同样呈现已选定的 A。

可试用新增账户、修改名称和余额、账户转账、关联流水跳转和成对删除，也可试用新普通流水对余额的影响。新流水只关联账户标识，账户改名后显示新名称。余额修正数据保留在演示状态中，不在产品界面展示。

本期不提供停用、账户删除或按账户筛选。页面仅展示新体系的模拟流水，旧流水不开放查看。普通流水仅演示账户接入，不替代已有退款等完整业务验收。

所有账户、金额与流水均为虚构数据，仅在页面内存中变化，刷新即可重置。不连接鉴权、数据库、Worker 或正式 API，不保存浏览器持久状态。

正式路由不接入此入口。启动使用独立 Vite 配置，不加载 Cloudflare 插件或本地业务凭据。正式功能后续以选定的 A 布局实施；本原型不直接合入生产。

# 01：新建并回看本人普通收支

## Parent

[个人账单规格 #90](https://github.com/PancrasDuan/lifespace/issues/90)

## What to build

获准访问 LifeSpace 的使用者从“财务”入口打开已确认的 A 方案，录入一笔普通支出或收入，在本人列表与详情中回看，刷新或换设备后仍可读取。首次交付就具备合法输入、账户隔离、事务和同次创建去重；后续日期筛选、退款与删除沿用本票的稳定契约。

## Acceptance criteria

- [ ] 接入现有导航、登录与准入，正式页面为 `/finance`；电脑和手机采用已确认的 A 布局，查看和新建使用居中卡片。保留原型、已确认交互和设计文档作为可供后续任务读取的依据，随本票按仓库流程纳入版本管理；不将模拟数据、重置入口、数据面板或账单调试日志带入正式页面。
- [ ] 从空账户即可新建普通收入或支出。默认支出，交易时间取打开卡片时当前北京时间、精确到秒，金额、账户、分类、备注为空；输入金额绝对值，按方向形成支出负数、收入正数，初始状态已完成。交易账户自由填写，备注可空，创建后不能编辑。
- [ ] 支出分类依次为交通、住宿、餐饮、购物、人情支出、充值、订阅、投资理财、其他；收入依次为工资、兼职、投资理财、人情收入、二手转卖、其他收入。固定单选、不预选，切换方向清空，非法或方向不符分类拒绝。投资买入 -1,000 与赎回到账 +1,050 按实际全额独立记录；充值仅用于向其他方充值，不用于本人账户间资金转移，不增加充值后消费跳过或合并规则。
- [ ] 金额采用有符号整数分，非零、元输入最多两位小数，单笔绝对值不超过 999,999,999.99 元；账户与备注 trim 后按 Unicode 码点限制为非空 50、可空 500。前端、接口及数据库执行对应边界，错误说明原因并保留输入，不截断文字；拒绝未来交易时间，允许补录。
- [ ] 交易时间数字保留原生分段编辑，其他输入区域打开独立日历与时分秒浮窗；小时 00–23、分秒 00–59，滚动、触控和键盘在边界停止，不循环或进位，滚动稳定后才可确认。确认才写回，取消、关闭、Escape 或外点保留字段原值及外层表单；桌面、390px 手机及短屏完整可用。
- [ ] 新建表单取消、关闭、Escape 或遮罩退出均直接丢弃输入，不二次确认或恢复草稿。保存成功仅关闭对应的当前表单，回全部时间第一页，仍按交易时间排序，补录不强行置顶、不新增刚保存流水入口；迟到响应不能关闭后来打开的新表单。
- [ ] 默认全部时间、每页 30 条，按交易时间与标识稳定倒序，具备基础翻页和单笔详情；列表展示完整交易信息。刷新或重新进入恢复全部时间第一页。进入、重新聚焦、手动刷新数据及成功写入后读取新数据，重新聚焦或刷新数据不丢正在填写的表单；明确区分加载、空态、读取失败、保存失败和结果未知。
- [ ] 仅建立流水与所有者版本两表，复用现有 Supabase 项目；流水保存可信 owner、唯一创建请求编号、不可变交易事实、可空同 owner 父关联、创建时间和逻辑删除时间。方向仅收入／支出，不另建退款类型、分类管理、回执或日志表。尚无数据的账户查询为空、版本 0，首次写入安全建立版本行。
- [ ] 本票固定后续可复用的共享请求／响应与错误契约：普通创建、列表和单笔读取；列表含 `items`、`total`、`page`、`pageSize`、`version`，每页固定 30，JSON 金额为整数分、时间为 UTC ISO 8601，普通 `parentEntryId` 为 `null`。列表、总数与版本一致读取；为后续日期与退款扩展保留已确认字段，不提供任意字段修改接口。未交付行为不暴露可执行入口。
- [ ] Worker 逐次核验身份与白名单，可信身份提供 owner；浏览器不接受任意 owner 或状态，缓存按 owner 隔离并沿用账户切换清理。两表开启 RLS，不向浏览器角色开放表或 RPC；服务端查询仍显式限定 owner，响应 `no-store`，稳定错误不泄漏凭据或账单正文。单笔越权、直接编辑及浏览器直访均被拒绝。
- [ ] 同 owner 写事务在版本行锁内完成查重、校验、插入及版本递增；失败完整回滚，独立普通创建不要求账户旧版本。创建请求唯一约束包含已删除记录，同编号同内容只生成一笔、返回原标识和当前版本，不同内容拒绝；不同编号同内容可分别保存，无实际新变更不递增版本。建立已确认的活跃时间与退款关联索引及同 owner 外键边界，不执行超出本票的退款或删除命令。
- [ ] 提交防重复点击。结果未知只在当前页面保留原请求编号供显式重试，不限制继续其他已交付操作，不自动重提、不持久保存命令，刷新或离开后不恢复旧提交。已确认保存成功但重读失败只重试读取；校验失败保留填写内容。
- [ ] 以正式财务页 → 真实 Worker → 隔离 PostgreSQL／PostgREST 完成桌面、手机新建与刷新回读；验证金额及码点边界、分类、时间、基础同秒分页、本人／他人隔离、首次并发写入、相同请求并发去重、同编号异内容、不同编号同内容、事务回滚及结果未知重试。扩展已有隔离数据库支持即可，不另造逐层替身；记录实际运行结果，跳过数据库套件不计通过。
- [ ] 按仓库流程先密钥扫描，完成相关接口、安全、类型、构建和浏览器检查及规范／需求双轴评审，提供当前分支预览供用户验收；具体 PR 合并取得明确确认，合并后核对部署、提交 SHA 与生产只读行为，再关闭本票。首次正式建表前只读确认现有结构，不影响其他业务或清理既有验收数据。

## Blocked by

无，可立即开始。

## Requirement coverage

父规格故事：1–21、23–26、35、37–38、47、49–50、58、60–64、66 的普通流水部分。退款、筛选及删除的组合行为由对应后续票扩展并验收；本票不得以未交付功能替代自身基础安全和持久化验证。

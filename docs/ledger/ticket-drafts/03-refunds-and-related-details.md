# 03：为普通支出追加退款并追溯关联

## Parent

[个人账单规格 #90](https://github.com/PancrasDuan/lifespace/issues/90)

## What to build

使用者从本人普通支出详情登记一次或多次退款，每次到账独立列为收入流水；能够查看父子关联，原支出金额保持不变，交易状态按全部有效退款自动变化。

## Acceptance criteria

- [ ] 在本人未删除普通支出详情提供登记退款卡片，时间默认为打开时的当前北京时间，金额和备注为空、不预填剩余额。交易账户、分类继承父支出并只读，方向固定收入、状态固定已完成；退款以独立正金额流水显示并有退款身份。
- [ ] 服务端固定父支出、账户与分类，不接受客户端覆盖。普通新建接口仍不接收父标识，方向只有收入／支出，退款通过收入且父关联非空识别；不另加第三种方向、退款标记或退款分类。支出分类例如餐饮可用于退款收入，不替换为普通收入分类。
- [ ] 父流水只能是同 owner、未删除的普通支出，普通收入、退款、已删除或他人记录均不能作父；复合外键及事务显式限制同 owner。退款金额非零、正数、最多两位小数且不超过单笔上限及剩余可退额度；备注 trim 后最多 500 码点，非法输入保留且不截断。
- [ ] 退款交易时间精确到秒、不早于父支出且不晚于服务端当前时间，同秒允许；沿用交易时间数字分段输入、独立浮窗、滚动稳定后确认、合法范围禁选及桌面／手机／短屏交互。
- [ ] 同一支出允许多次退款。所有未删除退款金额之和为零时父状态已完成，大于零而未全额为部分退款，等于原支出绝对值为全部退款且不再追加；原支出金额不扣减、不归零，普通收入及退款始终已完成。列表与详情按全部有效退款派生状态，不按当前页或查询范围局部求和。
- [ ] 父详情查看关联退款，退款详情提供父流水入口，相关读取只返回本人未删除数据，不受发起列表当前范围或页码限制。父子各按自己的交易时间参与列表，不将关联父流水插入当前结果；与 02 日期筛选的实际组合由 04 汇合验证，本票可独立于日期页面完成。
- [ ] 取消、关闭、Escape、遮罩退出直接丢弃本次输入并返回列表，不二次确认或恢复草稿；保存成功关闭对应表单、回全部时间第一页，仍按交易时间排序，迟到响应不关闭新表单。错误及结果未知处理沿用普通创建，不阻塞其他操作，不恢复跨刷新提交。
- [ ] 退款在同 owner 版本行锁内查重、核对父资格与额度、插入并递增版本，事务失败完整回滚。创建去重覆盖逻辑删除记录，先于父当前有效性和剩余金额检查；同编号同内容返回原标识与当前版本，不同内容拒绝复用。余额变少、已全额或父已删除后，旧成功请求仍不重建、不重新计入、不泄漏已删除正文；不同编号同内容在额度允许时可分别保存。
- [ ] 并发退款累计不超原支出，失败请求不留下部分流水或版本变更；退款写入使列表版本更新，并保持列表、总数和状态的一致读取。为后续删除与退款竞争保持同一 owner 事务锁和逻辑删除边界，不在本票开放删除入口。
- [ ] 通过正式页面 → Worker → 隔离数据库演示支出 -100、退款 +30 和 +70，三条独立流水、原金额不变、状态依次部分和全部；验证分类／账户继承、同秒时间及下界、父资格、跨账户读取与操作、并发超额、请求重试和事务回滚。删除前提的去重检查可用隔离夹具预置已删除状态；真实 UI 删除和完整竞争由 04 验收，夹具不得被表述为已交付删除功能。
- [ ] 本票沿用两表及现有鉴权链路、保护浏览器直访、拒绝越权和非法字段；记录实际数据库测试与桌面／手机体验证据，按仓库流程完成密钥扫描、相关检查、双轴评审、用户预览、具体 PR 合并确认与部署验收，再关闭。

## Blocked by

- 01：新建并回看本人普通收支。

## Requirement coverage

父规格故事：2–4、18、20–22、27–36、38、45–47、58、60–66 的退款部分。45–46 在无日期 UI 下先验证读取与派生状态不依赖列表局部结果，再由 04 在完整筛选页面复核；删除后的退款状态恢复与删除竞争归属 04。

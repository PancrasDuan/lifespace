# 02：按日期稳定浏览历史流水与多设备更新

## Parent

[个人账单规格 #90](https://github.com/PancrasDuan/lifespace/issues/90)

## What to build

使用者按北京时间选择日期范围，稳定翻看全部匹配流水；另一设备写入导致列表变化时，保留日期筛选、提示并从第一页重新读取。自定义日期仅应用后生效，读取更新不打断正在填写的表单。

## Acceptance criteria

- [ ] 沿用已交付的本人流水、30 条分页和稳定排序，接通正式页面、Worker 与真实数据库的日期查询。默认全部时间；今天按当日，近 7 天为今天及前 6 天，近 1 个月为含今天的 30 天，全部按 `Asia/Shanghai` 自然日，包含首尾。
- [ ] 查询使用 `startDate`／`endDate` 的北京时间日期，全部时间同时省略两者；服务端校验合法范围并转为开始日零点至结束日次日零点的左闭右开区间。设备时区和首页地区不改变账单时区，非法日期或反向范围不执行查询。
- [ ] 点击自定义打开独立双日历浮窗，左起始右结束，桌面并排、手机必要时上下排列，不推动原页面且不遮挡入口。本周填写周一至周日、本月填写月初至月末；均只改草稿，应用后才生效。
- [ ] 再次点击自定义、取消、Escape 或外点关闭并丢弃草稿，保留原筛选；重新打开恢复已应用起止日期。切换筛选从第一页开始，重新进入或浏览器刷新恢复全部时间第一页；普通流水成功保存仍回全部时间第一页，补录不置顶。
- [ ] 每页 30 条，全部匹配记录可翻页，同秒按标识稳定倒序，不漏不重；查询的条目、总数与版本在同一 owner 共享锁内一致读取，未删除条件始终有效，不能混合不同版本的页面。
- [ ] 分页携带可选列表版本；发现其他设备写入造成版本变化时，返回明确结果，页面提示列表已更新、保留日期条件并回第一页重新读取，不在旧页拼接新结果。重新聚焦和手动刷新数据沿用此一致性处理，不丢正在填写的表单、不引入实时推送；普通新建仍不要求账户旧版本。
- [ ] 查询缓存包含 owner 和日期／页码等条件；筛选快速切换或迟到响应不将旧条件结果显示成新范围数据。加载、无匹配、读取失败有明确区分，失败可重试；不增加筛选跨刷新持久化。
- [ ] 用真实页面 → Worker → 隔离数据库验证快捷日期、双日历草稿／应用／取消、跨午夜／跨月／闰日、首尾包含和非北京设备时区；至少 61 条含同秒记录验证筛选后的 30／30／1 及完整读取。两设备普通创建造成的版本变化不混页，且保留筛选、返回第一页，读取更新不丢表单。
- [ ] 用单 owner 累计 10 万条合成流水验证日期与深页读取、索引和稳定结果，记录环境、查询及实测结果；这是验证规模，不是产品条数上限或未经测量的性能承诺。只在隔离环境造数，不读取或清理生产账单。退款跨日期和删除后页码的组合由 04 汇合验证，不将其列为本票阻塞。
- [ ] 本票保持可信 owner 与受保护读取，记录实际隔离数据库执行证据，跳过不计通过；按仓库流程完成密钥扫描、相关检查、双轴评审、用户本地预览及具体 PR 合并确认，核对部署和生产只读结果后关闭。

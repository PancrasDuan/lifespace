# 04：确认影响范围后删除流水与关联退款

## Parent

[个人账单规格 #90](https://github.com/PancrasDuan/lifespace/issues/90)

## What to build

使用者确认交易和实际影响范围后删除普通流水或退款；删除支出时一并移除其退款，单独删除退款时恢复父支出的正确状态。提交前关联范围变化必须重新确认，删除后保留原筛选和有效页码，并在完整功能下验收录入、筛选、退款、删除的组合。

## Acceptance criteria

- [ ] 普通收入、普通支出和退款均可通过紧凑确认卡片删除，展示交易关键信息及不可恢复提示；父支出明确显示有效退款数量和联动影响。取消、关闭、Escape 或遮罩均不写数据，直接回列表，不返回原详情。
- [ ] 删除预览只读，返回本人未删除目标摘要及目标与全部有效退款标识所对应的影响范围。提交在数据库锁内比较使用者确认过的具体范围；新增、移除或替换退款导致集合变化时先不删除，重读并更新提示，等待再次确认。A 被删除而新增 B、数量相同也必须重确认；无关新建不使确认失效。
- [ ] 逻辑删除只写删除时间，原始金额、时间、账户、分类和备注不修改，不物理删除或提供恢复。删除父支出同时逻辑删除所有有效退款，不留下可见孤儿；单删一笔退款保留父及其他退款，按剩余未删除退款重新计算父状态；普通收入独立删除。
- [ ] 列表、详情、关联详情、退款计算与新增退款父资格一致排除已删除记录，任何旧详情不得继续读取正文或追加退款。所有预览、删除及关联读取显式限制可信 owner，知道其他账户标识也不能读取或操作，不暴露他人记录是否存在。
- [ ] 同 owner 行锁内重新核对影响范围、完成父子逻辑删除并只递增一次版本，同一次数据库提交成功或回滚。目标已删除时重复执行返回成功，不再次变更或递增版本；退款与父删除并发不能产生可见孤儿或超额退款。锁不跨用户确认或网络等待。
- [ ] 删除后重试原普通创建或退款请求不会复活记录、不返回已删除正文、不再增加版本；退款旧请求查重先于父已删除检查。当前页面删除结果未知可以安全重试或重新查看，不持久暂存、不自动跨刷新提交，也不阻止其他新建或退款。
- [ ] 本页成功删除保留当前日期条件和仍有效的页码；末页消失退回最近有效页，全部为空显示第一页空态，不错误采用新建成功后的全部时间规则。另一设备删除触发版本变化时，仍按 02 保留筛选、提示并回第一页，不混合版本。
- [ ] 实际页面验证 -100、+30、+70 后单删 +70 和 +30，父状态依次回部分退款、已完成且原金额不变；重新登记合法退款后删父，父子都不可见。验证普通收入独立删除、重复删除、已删除数据的所有关联访问与旧请求重试。
- [ ] 在真实数据库浏览器链路中验证预览后新增、删除、等数量替换退款的重确认，无关新建不干扰；验证父删除与追加退款竞争及事务失败回滚，不用单一 mock 或原型内存证明并发正确。
- [ ] 汇合验证 02 和 03：9 月支出、10 月退款只按各自时间进入列表，退款可打开范围外未删除父支出，父状态始终基于全部有效退款；筛选中追加退款成功回全部时间第一页，删除则保留筛选和有效页。覆盖同秒分页、多设备新增／退款／删除引发版本变化，以及关联目标删除后的反馈。
- [ ] 完整页面区分加载、无匹配、读取失败、保存失败与结果未知；重新聚焦／手动刷新数据保留正在填的表单，已成功但重读失败仅重读，迟到响应不关闭新表单。一笔结果未知不阻止其他操作，浏览器重载不恢复旧请求。桌面、390px 手机及短屏完成关键键盘、弹层与时间／日期流程；对照父规格 66 条故事核对完成归属，修复跨票组合缺口，不将前票应有测试留到本票补做。
- [ ] 使用合成隔离数据记录完整链路实际执行结果，核对数据库约束、事务、权限和 API 行为；复用 02 的 10 万条测量证据，并补充 03 引入的退款派生状态、关联查询及后续新增查询／索引变更的相应规模验证，普通流水测量不能替代退款加入后的查询证据。受控身份自动测试、真实登录／账户隔离、用户浏览器验收和生产部署分别记录，跳过的套件不能视为通过。
- [ ] 按仓库流程先密钥扫描，再完成接口、安全、类型、构建、浏览器及规范／需求双轴评审；提供当前功能分支本地预览并主动打开浏览器供用户验收，具体 PR 获明确合并确认后交付。核对 Cloudflare 部署、合并 SHA、生产页面及只读接口和密钥隔离后关闭本票；不因完成本票自动关闭或修改父规格。

# 个人账单系统需求草案

状态：本期产品需求已完成本轮确认，正式规格已发布至 [GitHub Issue #90](https://github.com/PancrasDuan/lifespace/issues/90)，标签为 `ready-for-agent`。此文件保留为本地需求核对稿，正式规格的本地副本见 [个人账单规格](issue-spec.md)；开发任务按项目约定登记到同一仓库的 GitHub Issues。

领域术语见根目录 `CONTEXT.md`，流水与退款的建模选择见 `docs/adr/0003-ledger-refund-entries.md`。

实施建议见 [技术方案](technical-design-draft.md)。使用者要求优先保证本期正常使用，不为罕见故障增加复杂交互。

数据库采用已确认的两表方案：`ledger_entries` 与 `ledger_owner_revision`；创建去重使用流水自身的请求编号，具体字段和约束见 [数据库设计](database-design.md)。

## 目标与范围

在现有 LifeSpace 的“财务”入口提供个人账单明细管理，支持手机和电脑浏览器，复用现有登录与准入机制。每个访问账户只新建、查看、登记退款和删除自己的流水，数据持久保存，刷新或更换设备后仍可读取。

每条账单流水都是独立流水。普通收入、普通支出不需要关联其他流水；只有退款流水必须关联一条普通支出流水。所有流水在明细中分开展示。

本期聚焦新建普通流水、追加退款、查看明细、日期筛选与删除。不提供编辑、恢复、收支汇总或图表；交易账户体系属于后续需求。交易分类已确认采用按普通收支分组的固定单选，具体清单见下文。转账与还款不在本次讨论范围内，暂不定义相关分类和业务规则。

## 流水字段

| 字段 | 完整性 | 普通流水 | 退款流水 |
| --- | --- | --- | --- |
| 交易时间 | 必填 | 北京时间，精确到秒；允许补录 | 独立记录退款实际发生时间 |
| 交易金额 | 必填 | 人民币；支出为负，收入为正 | 正数，代表本次退款金额 |
| 交易账户 | 必填 | 使用者手动填写，例如“招商储蓄卡” | 固定沿用父流水，不可另填 |
| 收支类型 | 必填 | 收入或支出 | 系统固定为收入 |
| 交易状态 | 必填 | 系统生成，初始为已完成 | 系统固定为已完成 |
| 交易分类 | 必填 | 从系统固定分类中选择，不允许自由填写 | 固定沿用父流水，不可另选 |
| 交易备注 | 选填 | 使用者补充说明 | 独立填写本次退款说明 |

“必填”表示每条记录必须具有该值；系统生成或继承的字段无需使用者重复输入。

普通流水和退款流水的单笔金额绝对值最高为 999,999,999.99 元，最多两位小数，不接受零金额；收支类型与金额符号必须一致。退款金额同时受父支出剩余可退金额限制。

交易账户与备注去除首尾空白后，按 Unicode code point（码点）计数：交易账户最多 50 个码点，不能为空或仅包含空白；普通流水和退款流水的备注均最多 500 个码点，允许为空。超出金额或文字上限时说明原因并拒绝保存，不静默截断。

交易分类必须为系统允许的固定选项。交易时间不得晚于当前北京时间；退款时间不得早于父支出的交易时间，允许与父支出发生在同一秒。

创建成功后不提供任何编辑操作。录入错误通过逻辑删除错误流水、重新录入处理；删除原支出会同时删除其退款流水。

## 固定分类

以下分类清单和固定单选方式已由使用者确认。普通流水按收入或支出方向选择一项，不允许自由填写或自行新增；无法匹配时，支出选择“其他”，收入选择“其他收入”。不做自动分类。

| 普通流水方向 | 固定选项（按此顺序） |
| --- | --- |
| 支出 | 交通、住宿、餐饮、购物、人情支出、充值、订阅、投资理财、其他 |
| 收入 | 工资、兼职、投资理财、人情收入、二手转卖、其他收入 |

退款继续遵守既定规则：方向为收入，但分类继承父支出，因此允许显示支出分类，不强制替换为普通收入分类。不另设“退款收入”分类。

已确认的记账口径：

- 投资理财按实际资金进出全额记录：例如买入支出 -1,000 元，赎回到账作为独立普通收入 +1,050 元，两条均选投资理财。
- 充值只用于向其他方充值，不用于记录向本人其他账户转移金额；转账和还款仍不在本次讨论范围内。
- 不采用此前“充值后余额消费一律不再记录”的建议，不增加这类跳过或自动合并限制。流水仍由使用者按实际交易手动记录。

原型使用固定下拉单选，初始不预选分类；切换普通收支方向时清空分类并重新选择。退款分类继承父流水并保持只读，不受普通收入分类菜单限制。交易账户继续手动填写。

## 新建与退款流程

普通新建默认支出，交易时间为卡片打开时的当前北京时间，精确到秒；金额、交易账户、交易分类和备注均为空。金额输入绝对值，界面与保存结果按收支方向呈现正负号。交易状态初始为已完成；普通收入始终为已完成，普通支出的后续状态由有效退款自动决定。

在普通支出详情中登记退款，系统绑定该支出并填入交易账户、交易分类、收入方向和已完成状态；退款时间默认为卡片打开时的当前北京时间，金额与备注为空，不预填剩余可退金额。使用者填写本次退款金额、时间及可选备注；创建退款后，它作为独立流水出现在明细中。

新建与登记退款表单通过取消、关闭按钮、Escape 或点击遮罩退出时，均直接关闭卡片、丢弃本次未保存输入，不二次确认，也不暂存草稿。取消登记退款后关闭卡片返回列表，不返回原流水详情。

交易时间字段保留直接点击数字进行分段编辑的方式；点击输入框空白、边框或日历图标，打开独立的日历与时间选择浮窗。浮窗沿用现有界面样式，日历选择日期，时间按时、分、秒分列选择。小时范围为 00–23，分钟与秒范围均为 00–59；浮窗时间列的滚动、触控与键盘选择在上下边界停止，不循环跳转，也不通过越界自动进位到其他时间段。

浮窗中的选择在确认后写入交易时间字段，滚动未稳定时暂不允许确认，避免写入滚动前的旧值。取消、关闭、Escape 或点击浮窗外部丢弃本次选择。仅关闭时间浮窗时保留外层表单。选择与直接输入均遵循禁止未来时间的规则；退款还须满足不早于父支出时间的限制。输入框上下空间不足时，浮窗居中使用可用屏幕高度。

退款父流水必须属于当前访问账户、尚未删除且为普通支出。普通收入和退款流水不能作为退款父流水，禁止退款再退款。允许同一支出发生多次退款。

设父支出金额为负数 `A`，原支出金额绝对值为 `P = |A|`，未删除退款金额之和为 `R`：

- 必须满足 `0 ≤ R ≤ P`，禁止超额退款。
- `R = 0`：父流水为已完成。
- `0 < R < P`：父流水为部分退款。
- `R = P`：父流水为全部退款，不再允许追加退款。

父流水交易金额始终保持 `A`，不会扣除退款、改为净支出或归零。新增、删除退款只通过累计有效退款影响父流水状态；退款本身保持正金额和已完成状态。

## 明细、分页与详情

界面已选定 A 表格方案。查看、新建及登记退款使用居中弹出卡片；删除使用尺寸更小、按内容自适应的二次确认卡片。

默认不限定日期，按各流水自己的交易时间倒序展示最近 30 条。超过 30 条分页，每页 30 条，可以继续查看更早记录。选择日期条件后同样按该顺序分页，返回全部匹配记录；切换筛选条件从第一页开始。同秒发生的流水仍需保持稳定排序，翻页不能漏记或重复。

分页读取时核对列表版本；其他设备新增或删除导致版本变化时，提示列表已更新，保留日期筛选并回到第一页重新读取，避免混合新旧列表。当前页面主动删除后的页码仍按下述既定规则处理。

新建普通流水或登记退款成功后，关闭卡片并切回全部时间、第一页。列表仍按交易时间倒序排列，补录旧交易不保证出现在第一页，不额外增加查看刚保存流水的入口。

删除成功后保留当前日期筛选和页码；当前页不再存在时退回上一有效页，没有流水时显示第一页的空状态。刷新或重新进入财务页时，恢复默认全部时间、第一页。

明细展示各流水的交易信息和退款身份，点击查看单笔详情。退款详情提供父流水查看入口，父支出详情可以查看关联退款。相关详情仅展示当前访问账户未删除的数据。

父子各自按交易时间独立参与筛选与分页。例如，9 月支出、10 月退款，筛选 10 月时只列出退款；可通过关联入口查看 9 月的未删除父支出，不把父支出插入 10 月列表。

父支出状态始终依据全部未删除关联退款计算，不受当前列表的筛选区间、页码或退款是否出现在当前页影响。

## 日期筛选

所有日期边界均采用北京时间（`Asia/Shanghai`），精确到自然日，包含所选首尾两天。

| 筛选项 | 范围 |
| --- | --- |
| 今天 | 当天 00:00:00 至 23:59:59 |
| 近 7 天 | 今天及之前 6 个自然日 |
| 近 1 个月 | 今天及之前 29 个自然日，共 30 天 |
| 自定义 | 通过日历选择开始日期和结束日期，开始日期不得晚于结束日期 |
| 自定义快捷键：本周 | 当前周周一至周日 |
| 自定义快捷键：本月 | 当前月首日至末日 |

点击“自定义”打开独立浮窗，原页面不展开日历或日期输入框。桌面浮窗包含两个并排日历，左边选择开始日期、右边选择结束日期；手机空间不足时上下排列，分别保留清晰标签。

“本周”和“本月”在浮窗内快速填充起止日期。选择过程保留为草稿，点击“应用”后才更新筛选；再次点击“自定义”、取消、Escape 或点击浮窗外部均收起浮窗、丢弃本次草稿，保留此前已应用的筛选。再次展开时恢复上次已应用的起止日期。

界面文案以字段、操作和必要反馈为主，删减页面标语、重复业务规则及表单说明；保留校验错误、删除不可恢复提示和关联退款的联动删除影响。

## 删除

采用逻辑删除：保留底层记录，从使用者可见范围排除，使用者不能恢复。列表、单笔详情、关联详情、退款计算和新增退款的父流水选择均排除已删除记录。

单笔删除前二次确认，并展示交易关键信息。删除父支出时，确认信息必须明确关联退款数量和联动删除影响；确认后同时逻辑删除父支出及其全部退款，不留下可见的孤立退款。

正式实现须在展示确认卡片时记录使用者看过的关联退款范围，提交时重新核对实际影响范围。范围不一致时先不执行删除，重新读取并展示当前影响范围，等待使用者再次确认；不能仅比较退款数量，数量相同但涉及的退款流水不同也须重新确认。此要求属于正式实现与验收范围，不表示当前内存原型已经实现跨设备并发处理。

取消删除确认、关闭确认卡片、按 Escape 或点击遮罩时，直接关闭卡片返回列表，不返回原流水详情，也不删除数据。

单独删除一笔退款只影响该笔，保留父支出及其他退款，按剩余有效退款重新计算父支出状态。普通收入独立删除。

## 保存、异常与隔离

- 进入页面、重新聚焦页面及成功写入后获取最新数据，提供手动刷新；刷新读取不丢弃正在填写的表单。本期采用此刷新方式，不引入后台实时推送。
- 必填或金额、时间、退款关联校验不通过时，说明原因并保留已填内容。
- 同一次保存因重复点击或网络重试只能创建一次；不同真实交易即使内容完全相同，也允许作为不同流水保存。
- 保存结果未知时提示结果尚未确认；仍在当前页面时保留原请求编号供安全重试，刷新后重新查看列表。不暂存交易命令或恢复旧提交，也不自动再次提交。
- 不因其中一笔结果未知而限制继续新建、退款或删除；每次操作独立处理。提交期间防止同一次操作重复点击，明确保存成功后再清空对应表单。
- 同时提交多笔退款仍不得超过父支出金额绝对值；父支出删除与追加退款同时发生时不能产生可见的孤立退款。
- 加载中、没有匹配流水、读取失败、保存失败须明确区分，失败时可以重试。
- 对单笔读取、关联读取、创建退款和删除逐次校验所属访问账户；知道其他账户的流水标识也不能访问或操作。
- 现有流水不允许通过界面或直接业务请求编辑；交易状态随退款事实变化由系统处理。

本期不建设备份与灾难恢复功能，按使用者最新明确要求执行。

## 验收案例

| 场景 | 预期结果 |
| --- | --- |
| 新建普通支出 `-100.00`、普通收入 `+100.00` | 分别独立保存并展示，初始状态均为已完成 |
| 打开新建流水并切换收入、支出 | 按指定顺序分别显示 6 项、9 项固定分类，切换方向后重新选择 |
| 打开普通新建或登记退款卡片 | 普通新建默认支出，两者时间均为打开时的当前北京时间；金额和备注为空，普通账户与分类为空，退款账户与分类继承且只读；退款金额不预填剩余额 |
| 在新建或退款表单填写内容后，通过取消、关闭按钮、Escape 或遮罩退出 | 直接关闭并丢弃未保存输入，不二次确认；再次打开不恢复草稿，取消退款返回列表 |
| 点击交易时间数字，或点击时间输入框空白、边框、日历图标 | 数字保留分段编辑；其他区域打开日历和时、分、秒选择浮窗，弹层不被表单卡片裁切 |
| 在可用的过去日期，将小时滚至 23 后继续向下、在 00 继续向上，分钟或秒滚至 59 后继续向下 | 均停在边界，不循环或跨段进位；键盘和触控遵循同样规则 |
| 时间浮窗取消、Escape 或外部点击；确认可用时间 | 取消只关闭浮窗并保留原值和外层表单；确认才更新字段，未来时间或早于父支出的退款时间不可确认 |
| 普通流水未选分类、指定不存在的分类或另一方向专用分类 | 拒绝保存；交易账户仍允许手动填写 |
| 父支出分类为“餐饮”，创建正金额退款 | 退款分类仍为“餐饮”且不可更改，允许保存为收入流水 |
| 投资买入 -1,000 元、赎回到账 +1,050 元 | 两条独立普通流水均选“投资理财”，不把赎回金额替换为收益差额 |
| 零金额、符号与类型冲突、超过两位小数、必填文字为空或未来时间 | 拒绝提交并保留输入；备注允许为空 |
| 单笔金额绝对值为 999,999,999.99 元或 1,000,000,000.00 元 | 前者在其他校验通过时允许，后者拒绝，不截断；退款还须满足剩余可退金额限制 |
| 去除首尾空白后，账户为 50／51 个 Unicode 码点，普通或退款备注为 500／501 个码点，含中文或 emoji | 50／500 的边界允许，51／501 拒绝，不静默截断；按码点计数，不按 UTF-16 代码单元计数 |
| 支出 `-100.00`，先退款 `+30.00`，再退款 `+70.00` | 三条流水独立展示；父状态依次部分退款、全部退款，父金额始终为 `-100.00` |
| 全额退款后再退 `+0.01`，或并发退款累计超出 `100.00` | 拒绝超额退款，不产生部分成功导致的超额记录 |
| 父账户为“招商储蓄卡”、分类为“餐饮” | 退款账户和分类固定为同值，不能指定其他账户或分类 |
| 删除上述 `+70.00`，再删除 `+30.00` | 父状态依次回到部分退款、已完成；父金额仍为 `-100.00` |
| 删除带有退款的父支出 | 确认联动影响后父子全部逻辑删除；页面、关联读取及退款计算排除这些记录，不能恢复或继续退款 |
| 父支出的删除确认展示后，另一设备新增或删除关联退款 | 提交时发现范围变化，本次不删除，更新影响范围并要求重新确认；再次确认前不能按旧范围删除 |

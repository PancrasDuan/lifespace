## 1. 建立和维护本人交易账户（#119）

**交付行为：** 在财务页 A 布局新增账户卡片区，能新增、查看、改名和修正当前余额，刷新后保持结果。

**阻塞依赖：** 无，可首先实施。

**验收条件：**

- [ ] 仅能访问和修改本人交易账户；新建名称及余额通过受控接口持久化。
- [ ] 账户标识稳定，名称去除首尾空白、1–50 个 Unicode 码点且本人范围内唯一。
- [ ] 初始余额及修正金额允许零、正数、负数，采用整数分，执行已确认金额边界。
- [ ] 改名只修改名称，不回写表单中的余额。
- [ ] 修正校验原余额；金额已变化时保留输入并提示重新核对最新值。
- [ ] 实际修正保存内部前后金额记录，但不显示为流水；重复请求不再次修改，无实际变化不新增记录或推进版本。
- [ ] A 布局卡片、新增与修改交互在桌面和手机可使用，不提供停用、删除账户或余额修正记录入口。
- [ ] 从正式页面到真实 Worker、隔离数据库验证持久化、名称冲突、修改冲突、重试、金额边界及所有者隔离。

## 2. 普通流水接入账户并联动当前余额（#120）

**交付行为：** 新普通流水选择本人账户，收支、退款和删除同步改变账户当前余额；旧未归属流水隐藏。

**阻塞依赖：** 1。必须已有可持久化的账户、余额及账户区，才能选择归属并观察结果。

**验收条件：**

- [ ] 新普通流水仅保存本人账户 ID，读取时显示账户当前名称；改名后列表和详情显示新名称，归属不变。
- [ ] 旧流水及旧名称内容保留，迁移前不通过列表、详情、关联读取和正常写入目标开放；不自动建账户或回填。
- [ ] 创建收入、支出和补录交易，与当前账户余额更新在同一事务完成。
- [ ] 退款固定沿用父支出账户和分类，保留原退款额度、时间、状态及父子关联规则。
- [ ] 普通流水、退款、支出及其退款的删除按确认范围撤销余额净影响；重复请求不重复调整余额或版本。
- [ ] 保持已确认的当前金额语义：1,000 元减 20、修正到 900、删除该支出后为 920 元。
- [ ] 金额联动超限时全部回滚，拒绝越权账户引用；新写入不保存账户名称快照。
- [ ] 账户、流水及详情按所有者隔离刷新，保留未完成表单；原有日期、分页及删除确认语义保持。
- [ ] 通过真实数据库与浏览器验证余额联动、父子删除净额、隐藏旧流水、现名展示、失败回滚及并发隔离。

## 3. 本人账户间关联转账（#121）

**交付行为：** 一次填写转出、转入账户及金额、时间、备注，创建关联的两条流水；可以关联查看并整组删除。

**阻塞依赖：** 2。复用已完成的流水账户契约、账户现名查询、余额事务及删除预览／删除路径。

**验收条件：**

- [ ] 仅允许两个不同的本人账户，金额填写正数，零或负余额不限制转账，最终金额必须在范围内。
- [ ] 同事务创建支出／转出、收入／转入两条等额相反流水，并更新两边余额；共享转账标识，单条流水标识仍各自独立。
- [ ] 原分类只增加转出、转入，原收支方向保留；普通新建接口不能生成转账单侧，转账不支持退款。
- [ ] 从任意一侧可以查看对侧，删除预览显示两侧，确认后同时删除两条并撤销两边余额。
- [ ] 无法单侧删除，重复删除不改变余额；删除范围校验不受无关写入影响。
- [ ] 使用已确认的请求号与转账组标识去重：同次重试不新增或重复扣款，同号不同输入拒绝，已删除请求不复活。
- [ ] 一次转账仅推进一次所有者版本，任一写入失败或金额超限时不留下部分流水、余额变化或版本推进。
- [ ] 真实数据库覆盖原子增删、失败回滚、并发与去重、跨所有者拒绝；桌面和手机完成转账、查看关联及整组删除。

## 实施及交付方式

三个子 Issue 已按 1 → 2 → 3 创建并设置原生依赖。使用 `implement-spec` 调度：每项由独立 Orca 子 session 在自己的分支和 worktree 运行 TDD，基于集成分支 `codex/118-financial-accounts` 的已提交版本开发；完成后由合并子 session 集成，再启动下一项。三个任务作为同一账户系统交付，不单独上线中间状态。

## 一致性与权限证据

- 新增角色／RLS 迁移在非空隔离库连续执行两次，十张既有业务表逐表行摘要未变。无 owner 上下文看不到个人数据，跨 owner 的 HTTP／MCP 操作被拒绝；角色不能读 Auth 表、删除历史、修改 owner 或调用旧写事务函数。
- 真实数据库确认共享读锁阻塞同 owner 写入，其他 owner 独立提交。TCP 代理等待版本 SELECT 的真实 `ReadyForQuery`，随后先提交首写、再放行旧读取，账户和流水都返回版本 0 的完整空快照。
- 失败写入完整回滚，成功／失败后连接从 `pg_stat_activity` 消失。TCP 代理在数据库 COMMIT 后丢弃成功响应，原请求重试只创建一个账户，不推进第二次版本。
- 退款／余额／转账竞争、第二侧流水失败、版本提交失败及删除失败均由真实数据库验证。新增一万条退款整组删除验证 SQL 集合范围和零净额恢复；金额不经浮点累计。
- 奖励 SQL 投影先移除历史回执，容量判断在传输前执行；75 项合法长说明来源超过旧 900,000 字节封套时返回 `CAPACITY_REACHED`，版本与经验不变。UUID 大小写遵从 PostgreSQL 身份语义。
- Agent 的真实启用绑定停用后，下一次 MCP 请求立即拒绝。外部 Access 验签与在线 Auth 用户检查保留，前端 SDK 会话不改。

## 延迟采样

2026-11-08，在本任务没有并行长测时，随机隔离 PostgreSQL 回环地址上采集每条路径 20 个有效样本，交替执行顺序，另预热 2 次。比较的是 Node 中的正式 pg 数据操作与热身 PostgREST RPC，不含真实 Auth 延迟、远端 TLS、Hyperdrive origin 池、placement 或跨区域网络。

| 操作 | pg 中位数／P95（ms） | 旧 RPC 中位数／P95（ms） |
|---|---:|---:|
| 开户 | 9.88／11.13 | 3.09／3.74 |
| 账户列表 | 6.87／7.60 | 2.62／3.33 |

本次迁移没有得到“所有链路更快”的结论。TypeScript 接管规则后，数据库仍提供约束、锁与集合执行；维护收益伴随更多语句和往返，Free 的每日语句额度须按实际业务操作计量。

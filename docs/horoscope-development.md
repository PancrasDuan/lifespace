# 星座运势开发核验

范围：#69 规格下的 #70、#71、#72；当前停在 #73 真实服务交付验收前。

## 实现

- 首页一张运势卡片，十二个名称与单色星座图标独立打开；首页不获取运势。
- 二级卡片正面显示日期、五项指数、幸运信息与来源，背面显示完整文字、提示和宜忌；翻转不请求接口。
- `GET /api/horoscope?sign=libra` 先执行既有认证和白名单检查，只接受唯一合法 `sign` 参数。
- ALAPI 成功内容标准化后按 `Asia/Shanghai` 日期与星座存入 KV，绝对期限为次日北京时间零点；不足 60 秒不写入。
- 缓存、上游、浏览器都校验内容归属与日期。跨日清除旧展示；昨日内容显示“今日运势暂未更新”。
- 缓存读取失败不回源；写入失败保留本次内容并进入 60 秒退避。实例内有限等待后复用已完成的普通数据，首请求未完成则返回忙碌状态，不共享在途 I/O Promise；回源间隔至少 1.1 秒；一般上游失败退避 10 秒，日额度耗尽保守退避至下一个北京日期。不承诺跨实例严格限流或仅回源一次。
- 正常卡片没有刷新按钮，失败状态可以“重新读取”；关闭恢复入口焦点，手机文字滚动，减少动态效果模式关闭旋转。

预览配置独立于默认构建配置，正式 Worker 不导入测试服务，没有测试专用认证入口或示例回退。预览测试日期按启动时的北京日期生成，测试值不表示真实运势。

## Standards

规范审查发现一项：跨请求共享在途 Promise 可能依赖首请求的 I/O 生命周期。已改为仅共享普通结果与时间标记，每个请求持有自己的有限等待；未完成时返回忙碌，避免跨请求复用 I/O。

## Spec

需求审查发现两项：部分 ALAPI 业务授权错误未分类、短横屏按钮可能裁切。已按官方错误表补齐授权/访问限制/额度类别，并用可收缩内容区保持操作区可达；均已加入回归。需求轴修复复核通过，未发现新增实质问题。

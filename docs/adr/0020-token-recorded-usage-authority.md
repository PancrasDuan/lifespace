# Tokscale 负责已记录用量，采集器负责校验和同步

2026-11-16，#223 首台真实设备因正常中止会话的 missing-usage 告警触发旧来源保护，21 天有效统计全部未保存。用户明确决定“可以信任 tokscale 的结果，我们只负责上报等工作”，并再次确认执行；[决定记录](https://github.com/PancrasDuan/lifespace/issues/223#issuecomment-6912379376)取代 [ADR0018](0018-token-source-coverage-and-local-queue.md) 中独立逐日志完整性证明及告警冻结策略。Tokscale 是唯一来源解析、继承／fork／归档去重和统计依据；不另建完整性或计数引擎。

从采集器 0.1.3 起，Tokscale 成功退出且通过版本、时区、JSON 结构、合法数值和日期／模型／总量一致性校验，即保存它报告的已记录用量。正常追加、新会话、missing-usage 及其他 stderr 不单独阻断有效结果，诊断只在本机以固定脱敏类别保留；不承诺恢复未记录消费，不把未知补成 0，不新增来源完整性上传协议或数据库迁移。停止全量读取原始日志进行 JSON／UTF-8／末行／压缩／日期／文件和祖先目录 stamp／前缀证明检查；旧 SQLite `sources` 表保留兼容，但正式采集不再读写证明。

Tokscale 失败／超时、无效输出或版本／时区冲突仍不替换旧汇总、不生成新待传任务；正常队列发送只能在严格匹配持久化回执后删除对应请求。新 graph 中缺席的旧日期保留旧值并记 `GRAPH_DAY_ABSENT`，不制造零快照或清空；有效重算可增加、减少或移除模型。规范化内容 SHA-256、不变不写、有序 generation／snapshotVersion、不可变重试和退避、独立心跳、设备授权、HTTPS、私有状态与单实例锁继续沿用。真实设备、正常网页登录、长期任务和人工验收分别留证，不由合成检查替代。

# 账户系统复用账单流水并扩展为四表

在现有 `ledger_entries` 和 `ledger_owner_revision` 基础上，新增 `ledger_accounts` 保存账户身份、名称和当前余额，新增 `ledger_balance_adjustments` 保存不展示的手工余额修正记录。当前余额随受控数据库事务直接更新，继续使用所有者行锁协调同一使用者的写入。

转账沿用原流水表的两条记录，通过新增 `transfer_id` 关联；同一事务维护两侧流水、账户余额和版本。选择共享组标识以保持本期结构简单，数据库约束与事务函数共同保障配对完整性，不再增加独立转账表。`category_code` 仅增加转出、转入两个分类，原有分类保留，`direction` 仍只有收入、支出。

转账的一次提交使用一个前端请求号，转出流水保存该号，转入流水使用数据库生成的独立内部请求号，两行另行共享数据库生成的 `transfer_id`。重试从原提交号定位整笔转账并核对输入，复用原结果，避免同次请求再次生成流水或改变余额，继续沿用原请求号唯一约束。

流水新增 `account_id` 并通过同所有者账户关系确定归属。旧 `account_name` 暂时保留用于后续迁移，新流水不再保存名称；旧未归属流水在迁移前隐藏。旧数据回填及旧字段清理留待上线后单独处理。

所有者版本表保留字段结构，账户及流水的实际写入统一纳入协调和版本推进；一次转账只推进一次版本。新增的账户与修正记录表服务于已确认账户业务，[撤销跨刷新恢复](0004-ledger-pending-operations.md) 的决定继续有效。

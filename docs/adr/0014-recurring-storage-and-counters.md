# 周期父规则独立保存，完成子任务复用任务与事件

2026-11-15，#198 的工程决定；业务依据为固定提交 `3a45dab02e59cf1ac486b86a313463acbcbfe2e4` 的 #56 最终规格及 [ADR 0013](0013-recurring-periods-and-completion-facts.md)。以现行四表与目标分类模型为起点，新增 `adventure_recurring_tasks` 父规则表；每次完成在 `adventure_tasks` 新增 `kind=recurring_child` 的稳定子身份，并在 `adventure_events` 复用 `task_completed`／`task_completion_cancelled`。本票只冻结设计，SQL、Worker 路由和真实数据库验证属于 #199。

独立父表将锚点、要求、生命周期与完成周期计数集中保存，父对象没有一次性任务的 `planned_on`、待办或完成状态。相比把父、子、一次性任务都塞入任务表，它避免父行被旧 `task_completed`、计划日期和唯一有效完成索引误当成一次行动。相比另建完成事实和奖励体系，复用每个子任务独立 `taskId` 与完成事件，能保留现有行动去重、成长、奖励来源、owner 外键和成功回执；现有一次性查询必须显式限制 `kind=once`，新的统一日期读取再合并生效子任务。

父表仅保存 `completed_periods`、`tracked_period_no`、`tracked_period_satisfied` 三个计数维护字段；不保存本期完成次数、进度百分比或逐期快照。写事务先按当前权威日期推进维护期：旧贡献已经包含在累计内，跨期只将维护期移动至当前期、清除其贡献位，不减旧累计、不为跳过的空期加数。同一期内用本次操作后满足位减操作前满足位增减累计；有效次数始终聚合该父、该期的未失效子完成。所有影响次数、要求及生命周期的操作，与事实、XP、revision 和回执在同一账户锁事务中完成；重放只返回原回执。

只读请求不写维护状态：从存储状态投影到当前期，过去期的贡献留在累计中，当前期次数从事实求取。没有行动的期不会满足正整数要求，因此长时间无访问时可直接跳至当前期，不需要定时任务或逐期记录。父结束时停在真实结束日的期数／进度，之后不再推进；历史期结果只冻结在累计和操作审计中，不用当前要求重算过去。

完整字段、owner 复合关系、整数／日期上限、差量算法、操作审计和新库／非空升级门禁见[共享契约](../adventure/recurring-contract.md)。该设计未改变 ADR 0010 的目标结构或 ADR 0011 的 historical_lock 删除决定，也不授予生产操作权限。

# 人生冒险使用关系表与服务端事务

状态：2026-10-20，用户确认改用多物理表方向，具体表及事务方案为设计稿，暂不实现。

## 决定

使用 public.adventure_ 前缀的十张物理关系表分别保存账户元数据、主线、目标、稳定任务、安排历史、完成事实、目标达成、奖励、计奖关联和命令回执。当前归属、状态、日期、金额与 ID 使用真实列及同 owner 复合外键，不再持久化整账户 JSON state；JSONB 仅存不可变快照及稳定操作回执。

Worker 在线验证账户和准入；浏览器无直接表或事务函数调用权限。最终业务校验和更新在服务端专用 SECURITY INVOKER 数据库事务 Module 内完成，能力与预览复用后端判定函数，不让前端或 Worker 重复计算奖励、配额或终态。

命令先锁 adventure_accounts 的 owner 行，查回执并核对 revision，同事务写入所有事实、奖励、计奖关联、revision+1 和成功回执。保留账户级 expectedVersion，未知结果使用原请求身份重试，普通冲突要求重新读取确认。多表读／预览使用短事务共享账户锁保证一致，事务不等待用户确认或调用外部服务。

## 选择理由与代价

独立关系表可以使用真实外键、有效完成部分唯一索引、来源唯一键和计奖关联，按记录查询与分页；不再依赖整账户 JSON 解析、重写或单行容量上限。代价是需要明确多表事务、循环引用的延迟外键、索引与函数权限，不能把多次 REST 写入视为原子操作。

本期保留账户级版本与锁，因此同一账户不同任务仍可能冲突；不把拆表误述为已解决所有并发或性能问题。等级和成就实时计算，不单独存状态或日期；取消完成及对应奖励逻辑删除，稳定历史和回执不裁剪。

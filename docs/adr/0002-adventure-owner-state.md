# 人生冒险使用五张关系表和事务事件

状态：2026-10-20 用户确认五表方向，设计稿，暂不实现。

## 决定

人生冒险使用五张 public.adventure_ 物理表：

- adventure_accounts 保存账户、total_xp、revision、时区及时间。
- adventure_mainlines 保存普通主线和按需创建的独立主线。
- adventure_goals 保存真实目标及按需创建的唯一 inbox 系统目标。
- adventure_tasks 保存一次性任务当前内容、当前执行日期、归属和状态。
- adventure_events 保存操作历史、完成／取消、奖励、计奖依据、快照和成功请求回执。

所有业务写入通过后端专用数据库事务 RPC。事务锁账户行、查成功回执、核对 expectedVersion，在同一提交中写当前实体、事件、total_xp 和 revision。事件不可物理删除；完成取消只逻辑失效对应事件和任务奖励，旧 requestId 重试仍能读回历史回执。等级、成就、本级进度和操作能力实时计算，不单独存表。

## 关键取舍

五表比单行 JSON 提供真实外键、索引和按记录读取；比十表减少安排、完成、奖励、达成和回执的辅助表。任务表只保留当前执行日期，改期历史交给 events；目标达成字段并入 goals，计奖行动 ID 冻结在目标行与 reward_goal 事件中。

账户 total_xp 是事件奖励汇总，必须由事务与事件同步更新并可核对；不是另一套独立账本。历史奖励与完成事件不能按“当前有效”过滤后再做幂等查询，否则已取消完成可能被旧请求重新发奖。

独立主线与 inbox 按首次需要创建并复用，不预建；独立任务仍有关联 goal_id，但页面展示为独立任务。inbox 不参与真实目标生命周期、聚焦、成就或目标奖励。保留账户级版本，拆表不自动解决同账户并发冲突。

# Token 在本地汇总，模型分类与内容指纹独立于身份

> 阶段05 #219 统一集成时由原 `0016-token-local-rollup-contract.md` 重编号；main 的 ADR0016 记录旧机器绑定退役。原决策可追溯至 #206 / PR #208 和提交 `8b970d1`，内容不变。

#205／#206 延续用户在 #79、#82、#83、#85 确认的本地统计方向：TypeScript 采集程序调用固定并验证过的 Tokscale CLI，复用上游来源解释、设备内去重与计价；不导入旧独立 core 包，也不自建另一套日志解析或价格引擎。首期为 Codex，macOS/Linux 分别计量，不跨设备去重。以“设备标识 + Asia/Shanghai 日期 + 来源 Agent”确定主汇总，模型为同一范围的子统计，分类与主汇总不重复相加。

实际内容只含指标、完整模型分类及解释它们所需的模型/提供方标识、币种和费用状态。SHA-256 对这些内容规范化后计算，排除身份、schema/统计/工具/价格/快照版本、hostname 和扫描时间；摘要不是主键、权限凭据或顺序版本。已确认的服务端方向仍是同时验证内容与摘要、以有序快照版本防回退、在事务中替换主汇总与子统计。版本生成、恢复队列、RPC/回执属后续阶段，当前契约不伪造可用上传链路。

选择粗粒度汇总降低云端处理与隐私成本，相应地规则或价格修正由本地重算；最新汇总与 Tokscale 缓存不能恢复已删除日志的全部事实。缺少来源时不能用不完整重算覆盖已有历史。未知、缺失与零分别表达，API 估算不能当成实际订阅账单。4.23.0 的 graph 直接提供日期×Agent×模型联合分项，`mixed` provenance 没有金额拆分时保留为未分类费用，不能按比例猜测。

后续本地 SQLite 保存最新结果及不可变待传快照；应用专用设备标识由系统标识派生，hostname 仅作显示名。设备码与网页登录确认领取独立上传凭据，登记/授权由 Worker 承载，日常上传直达 Supabase HTTPS RPC。现有通用 Worker+pg/Hyperdrive 访问方式不改变此方向。本阶段不操作数据库、权限、凭据、定时任务或正式页面。

实现与可复现样本见 [统计契约](../token-usage-contract.md)、[固定上游调查](../tokscale-206-upstream-research.md)。源工作区未提交 ADR 的编号 0011 及实现期间 main 新增的 0015 均已被其他决策占用，故以当前编号新增，不覆盖既有决策。

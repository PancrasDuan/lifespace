# 设备登记代际与快照版本共同防止恢复后的旧请求回退

#209 延续 #205／#82／#83／#85 和 ADR 0019。每次经浏览器确认并成功领取的登记，由数据库在设备锁内递增授权代际，同时轮换令牌；每份主汇总以 `(generation, snapshotVersion)` 比较先后。设备身份只定位设备，不能获得上传权限；丢失 SQLite 或凭据时必须重新登记，使新代际可从版本 1 恢复，而旧代际的令牌与在途请求立即失效。代际内版本由下一阶段采集器在本地持久化事务中分配，不能按扫描时间或内容摘要排序。

高熵领取凭据来自 32 个随机字节，上传凭据通过请求 UUID 为 salt、独立用途标签为 info 的 HKDF-SHA-256 派生 256 位输出。两者具有独立摘要、入口和权限；上传令牌不能反推出领取凭据。领取窗口内重试可重建同一上传令牌，数据库只保留摘要，避免存储可解密令牌或因响应丢失再次轮换。短码只供已登录白名单账户核对设备，不能领取权限；重新绑定现有设备须明确确认。具体接口、恢复、权限与上线门禁见 [服务端契约](../token-backend.md)。

只有两项匿名上报 RPC 使用受限 `SECURITY DEFINER`：设备不具有浏览器账户身份，不能要求 `auth.uid()`；函数固定空 `search_path`，在同一事务内检查专用请求头、设备绑定及启用状态，并锁定设备后处理数据。底层表/辅助函数位于未暴露的私有 schema，匿名和浏览器角色均无访问权限；登记管理和共享只读查询只给 Worker service role，浏览器仍按 ADR 0001 在线核验会话与当前白名单。此边界不恢复 ADR 0015 已退役的旧 MCP 通道。

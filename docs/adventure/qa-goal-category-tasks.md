# 目标分类下的任务和成长回归

在本机安装 PostgreSQL 和 PostgREST 后，设置 `POSTGRES_BIN`、`POSTGREST_BIN` 和必要的动态库路径，运行：

```sh
npm run test:adventure-task-database
```

运行器分别创建随机临时 PostgreSQL 集群和回环端口，并在结束时清理。第一轮初始化四表结构，运行任务编辑、删除、逾期、日期列表、统一改期、生命周期、成长、奖励来源和跨功能回归，并核对任务、经验、冻结奖励、安排链和回执的一致性；第二轮以合成非空五表旧库执行迁移，验证旧成功请求、已失效完成、摘要冲突、历史终态锁定和奖励来源。旧主线命令、目标跨主线迁移和按主线聚焦配额已退役，回归改为检查其新请求被拒绝；目标全局排序由目标契约验收覆盖。

任务和目标命令、workspace 读取、预览、日期列表、任务历史、成长和奖励来源均经过真实 Worker HTTP、PostgREST 和 PostgreSQL。历史日期及保留聚焦值由仅安装在临时库的测试夹具构造，它们不安装到生产数据库。

`npm run test:database` 是更完整的默认入口：先在隔离旧五表库执行原 SQL 回归和旧日期规则升级，再在独立四表库执行任务与成长 Worker 回归及全库审计，并在另外的隔离旧库执行目标／任务历史回执的真实升级与 Worker 测试。四表库还直接注入完成、取消及目标终态的事务故障，核对完整回滚，并验证旧大额冻结奖励的预览和取消。最后实际运行目标分类迁移的逐账户对账、新库与升级库验证、权限探针、故障回滚和重复执行检查；任何阶段失败都会使入口失败。旧 SQL 只验证升级前契约，四表行为和迁移安全由后续阶段独立验证。

上述数据库入口不替代 `npm run test:database -- --goal-model --browser` 的真实浏览器回归或生产迁移验收。

`--browser-only` 必须同时指定 `--browser`；`--api` 和浏览器筛选参数会在结果中列出实际范围，不能视为无参数的完整验收。HTTP 和浏览器阶段读取结构化测试报告，列出执行、通过和跳过数量，并在零通过时失败；报告器由入口固定，不能通过参数覆盖。`npm run test:database:runner` 使用隔离数据库和本地浏览器自动验证参数、范围报告、全部跳过负例以及无参数全量入口，运行它需要数据库和浏览器测试的本机依赖。

# 目标分类下的任务和成长回归

在本机安装 PostgreSQL 和 PostgREST 后，设置 `POSTGRES_BIN`、`POSTGREST_BIN` 和必要的动态库路径，运行：

```sh
npm run test:adventure-task-database
```

运行器分别创建随机临时 PostgreSQL 集群和回环端口，并在结束时清理。第一轮初始化四表结构，运行任务编辑、删除、逾期、日期列表、统一改期、生命周期、成长、奖励来源和跨功能回归，并核对任务、经验、冻结奖励、安排链和回执的一致性；第二轮以合成非空五表旧库执行迁移，验证旧成功请求、已失效完成、摘要冲突、历史终态锁定和奖励来源。旧主线命令、目标跨主线迁移和按主线聚焦配额已退役，回归改为检查其新请求被拒绝；目标全局排序由目标契约验收覆盖。

任务和目标命令、workspace 读取、预览、日期列表、任务历史、成长和奖励来源均经过真实 Worker HTTP、PostgREST 和 PostgreSQL。历史日期及保留聚焦值由仅安装在临时库的测试夹具构造，它们不安装到生产数据库。

原 `npm run test:database` 仍包含旧结构 SQL 和依赖旧目标界面的完整入口，需在目标契约集成后迁移并重新运行。上述专项回归不替代该入口、完整浏览器回归或生产迁移验收。

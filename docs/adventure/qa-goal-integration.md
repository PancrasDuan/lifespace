# 目标分类集成与维护窗口（#174）

交付分级为需确认：涉及核心规则、历史迁移、权限与公开接口。本地实施和隔离验证已获授权；生产迁移、生产备份／恢复、合并与发布未获授权。#168 的历史清理规则覆盖 #164 早期“快照保留原值”：仅删除主线信息与纯主线操作历史，保留其他事实；旧完成和达成不伪造分类快照。D32–D35 与 ADR 0010 是已确认决策。

## 维护窗口方案（待演练及批准，不能直接执行）

角色：窗口负责人负责停止／继续决策和记录；数据库操作员负责一致性备份、迁移与逐账户对账；应用操作员负责维护门禁、版本路由及客户端切换；独立复核者核验备份恢复、对账和门禁。时间、责任人、实际系统入口、回退阈值、备份位置与保留期限必须在生产授权前明确，所有步骤记录 UTC 时间、版本 SHA、数据库版本、结果和负责人，不记录敏感数据。

1. **预检**：固定并复核数据库迁移、Worker、客户端构建 SHA 和部署依赖，确认已有版本及恢复所需工具、权限、容量、监控、通信和窗口时长。盘点写入者（浏览器、旧标签页、排队请求、重试、后台任务、直接数据库／RPC 和管理员）、所有 adventure 对象、权限及快照载体；检查映射、标签长度、外键、索引、异常授权和每账户经验一致性。异常时停止，不截断、跳过或修复真实数据。先在独立隔离环境用同版本和代表性合成数据完成升级、故障、恢复及兼容演练。
2. **冻结和备份**：在所有入口启用维护模式并验证冒险写操作失败，排空在途请求，停止后台写者及直接访问；数据库侧撤销或隔离写凭据并确认无活动写事务。全程保留门禁，读取也须挡住以免新旧契约混用。记录冻结点及每账户 revision、total_xp、目标／任务／事件 ID 与保留字段及排序的基线。使用经过审查的生产备份方式建立一致性备份，校验完整性、加密、访问控制及恢复点，并在独立环境实际恢复核对；没有可验证的备份和恢复路径则中止。
3. **升级与对账**：数据库操作员在冻结窗口执行固定版本迁移。单事务失败应整体回滚；确认提交结果及 schema 刷新后，逐账户逐 ID 比较目标／任务和非纯主线事件、状态、排序、奖励、快照、回执、revision、total_xp 与有效奖励之和，检查 inbox 唯一性、约束、权限、账户隔离、历史锁定、主线结构／嵌套快照清除及旧回执安全重放。不得只比较行数。任何失败或不明结果保持冻结并调查；禁止通过重跑掩盖不一致。
4. **一致切换与旧客户端**：在门禁后装载同一版本的新数据库、Worker 和客户端，核对版本与静态资源缓存。切换非原子时，先在隔离环境验证一个服务端强制版本门禁：所有旧客户端写入及重试在任何写入前拒绝并保留未知状态，直连 RPC 在外层阻断；缺少或错误版本也拒绝。旧标签页及缓存不能凭 revision 充当客户端版本证明。验证旧深链接与旧参数明确退役，新客户端读取和命令可用，再由负责人共同确认后开放。本分支的 Worker 命令入口要求 `X-Adventure-Client-Version: goal-categories-1`；缺失或其他值在进入数据库之前返回 503，并提示不要刷新或重新提交、联系维护人员；旧客户端将 503 保留为未知结果，当前客户端发送该头。此头是兼容协议，不是安全凭证，也无法保护旧 Worker 或直连数据库。外层部署架构、旧地址封闭、缓存失效及维护门禁仍待实际验证，是上线阻断项。
5. **回退**：先重新停止所有写入并排空在途请求，记录冻结点；盘点迁移提交后每账户全部新增／修改事实、回执、revision 和奖励。若已有新写入，先保存可恢复副本并逐项制定经批准的导出、转换、重放和冲突解决方案；没有经过验证且获授权的无损方案就保持冻结，不以旧备份直接覆盖。无新写入时也须验证恢复目标、备份完整性和应用版本一致性，按获授权的恢复程序恢复并对账，再切回匹配的旧 Worker／客户端，验证权限、读写和旧契约后开放。任何不确定性继续保持冻结并升级处理。
6. **保留与再次清理**：迁移前备份仍含主线历史，不属于在线清理完成。生产执行前指定加密位置、访问者、审计、保留期限、删除负责人和到期销毁证明；未决定期限前不得开始生产操作。恢复旧备份会重新引入主线，在再次开放新版本前必须重新冻结、执行同版本迁移与逐账户对账并确认结构化清理，不能只依赖此前清理结论。

## 旧页面未知结果：冻结与人工核对

旧版 `ff015c0512666a34764d719bc36015cb0a3b387b` 只在运行中的页面内存保留封套，关闭、刷新、浏览器崩溃或重挂载会丢失它；服务端无法从旧页面取回内存。503 只缓解页面仍打开且后续重试能到达门禁的情况，不保证断网期间用户看到提示。不得要求未知结果用户刷新、关闭或再次创建；无法联系用户、识别其账户和请求、或核对存在歧义时保持该账户及相关写入口冻结并升级人工处理，不以标题、时间相近或当前行数猜测，更不能用新 requestId 盲目重做。

1. 冻结全部冒险读写并排空旧服务的在途事务；对用户说明保持旧标签页不动，记录已知操作、受控账户、可能的响应丢失时间，不记录敏感内容到公共工单。若网络面板在原请求发生时已记录完整请求，可在用户授权下由受控人员保全原 requestId、expectedVersion 和命令封套；若无法取得原封套，记为无法自动判定，不制造请求或用近似数据替代。
2. 通过可信会话或经授权的身份核验确定账户；核对封套属该账户。受控数据库操作员用**只读事务**、参数化查询按 `(owner_id, request_id)` 查事件，并按切换前实际旧 Worker 的输入规范化结果计算 `sha256(convert_to(command::jsonb::text,'UTF8'))` 比较 `command_hash`。expectedVersion 保存在封套中，但不在命令摘要中；不能仅凭摘要声称校验了该字段。保持事务只读、记录审计标识与布尔结论，不把原命令、快照、身份或密钥写入日志、浏览器、工单或公共输出。匿名和 authenticated 无权读事件；service_role 可跨账户读取，因此仅在受控操作环境、按已验证账户查询，最小权限和真实访问审计需在生产前验证。
3. 若同账户有事件且摘要匹配，检查该非纯主线回执可安全重放并确认结果已清理；不安全的旧结果保持 `REPLAY_UNAVAILABLE`，不得展示主线或执行新动作。已确认时记录成功和对应冻结事实；使用新服务的只读回执查询接口确认结果；普通命令入口遇不到回执可能执行新命令，不能把它当成纯查询。若摘要不符，按 `REQUEST_ID_REUSED` 冲突处理，禁止执行。无匹配事件不等于没提交：纯主线事件／回执已删除、旧备份／迁移状态或封套不完整都可能造成缺失；保持冻结并人工核实，不能自动执行或重做。
4. 经独立复核确认用户看到的结果、账户事实和奖励后，才安排切换到新页面；无法证明结果或保全封套时不能自动恢复，必须先制定并获得批准的个案处置。未知结果跨刷新／关闭没有自动恢复能力，是当前方案的限制。

可审阅的后续方案：先设计并单独验证**兼容旧数据库的过渡客户端／Worker**，在迁移前持久化账户绑定的原封套、在未知状态下阻止刷新丢失并提供清晰的核对／恢复入口；在最外层为新导航提供不可缓存的维护页面，旧 API 一律返回保留未知状态的 503，先完成活跃客户端引导、排空和账户核对，再冻结并迁移。服务端不能强制已打开、断网或缓存的旧 JS 修改 UI，也不能证明所有历史标签已升级；过渡方案尚未实现、验证或授权，不能单靠这份计划满足旧页面的明确退役提示。旧 GET 在真实旧构建中掩盖服务端错误而显示通用连接提示，已打开页面没有可达的强制刷新提示；该项连同外层全入口封闭和未知封套的跨关闭恢复仍是上线阻断。

真实旧构建演练：从固定 `ff015c0512666a34764d719bc36015cb0a3b387b` 构建静态资源与旧 Worker，在随机本机临时 PostgreSQL／PostgREST 中加载五表；旧 UI 发出命令后让旧 Worker 提交并丢弃响应，合成代理冻结读写、迁移、再由新 Worker 拒绝旧请求。验证旧 UI 保留同一封套、账户版本和 XP 不变，按账户／编号／摘要只读核对成功、不同摘要或其他账户不匹配、缺失回执不触发执行，以及新客户端相同封套查询不重复；事务未提交时查询返回未知，提交后返回原回执，其他账户查询不创建账户。恢复后旧静态构建的首次读取与旧主线链接均只显示通用连接错误。`anon`／`authenticated` 读取事件被拒绝；测试代理是进程内合成网络边界，不能证明真实 Cloudflare 路由、旧地址封闭、真实用户身份或生产权限。复跑需先将该固定提交 `git archive` 到独立临时目录、按项目 Node 版本构建，再设置 `OLD_ADVENTURE_DIST`、`POSTGRES_BIN`、`POSTGREST_BIN` 和 Chromium 路径运行 `node tests/support/run-old-client-cutover.mjs`；运行器自行创建并删除临时集群，不接受现有数据库地址。


### 过渡客户端的只读协作契约

迁移完成、PostgREST schema 已刷新并经验证后，获准访问的新服务提供 `POST /api/adventure/receipts/lookup`。调用者必须使用原账户的有效会话、提交原始 `requestId`、`expectedVersion` 和 `command`；Worker 不接受客户端指定 owner，并按原命令规则规范化后调用仅 service_role 可执行的只读 RPC。该接口不需要新写入版本头，不创建账户，不执行命令、不发奖、不修改版本。跨账户相同编号按本账户查询；Worker 身份隔离不意味着数据库 service_role 自身受账户限制。

- 同账户的编号和规范化命令摘要相同，且结果可安全返回：200，返回清理后的原成功回执，并携带 `X-Lifespace-Adventure-Model: goal-categories-1` 和 `Cache-Control: no-store`；过渡客户端必须核对两个响应头并严格验证回执结构，缺失或不匹配保持未知。该标识不是认证。该摘要不含 `expectedVersion`，接口不会证明原版本字段与第一次请求相同；调用方仍应保留原完整封套。
- 同账户编号存在但摘要不同：409 `REQUEST_ID_REUSED`，停止并核对，不能更换编号重新执行。
- 未发现可用回执，包括其他账户或被删除的纯主线历史：404 `RECEIPT_UNKNOWN`；这不是未提交证明，尤其在事务尚未提交、日志丢失或纯主线回执已清除时。不要自动调用普通命令接口或用新编号重做。
- 旧结果无法安全返回：409 `REPLAY_UNAVAILABLE`，不得泄露主线信息或执行新动作；其他错误、网络中断及 schema 未就绪同样保持未知，直至人工核对。查询事务未看到仍在途的写入时会返回未知，维护窗口必须先阻断并排空所有写事务。

此接口可供兼容旧库的过渡客户端在安全切换后查询已持久化封套，但不会使现存旧页面获得新功能。过渡客户端不得给旧封套添加 `goal-categories-1` 后自动调用普通命令接口；没有原封套或账户匹配证据时不能自动恢复。当前过渡版本尚未实现或部署；真实 Cloudflare 全入口门禁、缓存刷新、身份与访问审计仍待独立验证。

### 模型握手和切换竞争

过渡客户端先经本人认证调用 `GET /api/adventure/compatibility`，不得根据旧服务对查询接口的 404 推断模型；响应必须为 `Cache-Control: no-store`。新 Worker 明确返回 `{ "model": "goal-categories", "version": 1, "receiptLookup": true, "legacyRetry": false }`，表示 Worker 接口能力而非数据库迁移、schema 刷新或维护门禁已经就绪。过渡旧 Worker 的拟议对应响应为 `{ "model": "legacy", "version": 1, "receiptLookup": false, "legacyRetry": true }`；该旧服务尚未完成集成部署，最终值需双方验证。缺少字段、未知版本、认证失败、网络错误或不明确响应时继续保留待决封套。

过渡客户端仅在收到旧模型明确握手时，使用 `POST /api/adventure/legacy-retry` 携带原账户的原封套，在旧模型上按原 requestId 安全重试；如果旧模型握手后在发送重试前发生切换，新 Worker 的同一路由经过认证后无条件返回 503、禁止缓存、提示不要刷新且不读取或写数据库，不解析封套，也不降级调用普通命令。保留封套后重新握手；只有新模型明确支持查询时使用上述只读接口，任何未知结果继续待决。外层必须阻断并排空旧 Worker，关闭绕行地址，不能依赖此握手替代部署隔离。真实旧构建没有过渡能力；本机演练中的旧模型握手是测试代理模拟，不能当作旧过渡 Worker 已验证。

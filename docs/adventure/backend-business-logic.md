# 后端业务逻辑设计

状态：2026-10-20 多关系表设计稿，暂不实现。依据 [规格](spec.md)、[成长与奖励](growth-rewards.md)、[前端设计](decisions-frontend.md) 和 [数据库设计](backend-database.md)。业务行为不变，写入方式改为服务端专用数据库事务，不提前确定完整 HTTP 契约。

## 模块与规则归属

| Module | 职责 |
|---|---|
| Worker 请求处理 | 在线验证会话及准入，确定可信 owner，严格校验输入类型与封套；调用后端事务／读取入口，映射错误，不重复编写计奖、终态或配额算法。 |
| 数据库事务 Module | 在一个事务内完成最终业务校验、关系表写入、版本递增和成功回执；能力和预览复用同一套后端规则函数。 |
| 读取与投影 Module | 在一致版本下查询所需记录、分页列表、有效奖励汇总、等级、七个成就、操作能力和影响；不持久保存派生成长状态。 |

本期采用服务端专用 SQL 函数 RPC 承载事务 Module。其函数名和内部拆分是后续实施设计，不等于前端 HTTP 接口。调用角色仅限后端，浏览器不能直接调用；不提供任意 SQL、任意表名或整账户 JSON 写入入口。

## 事务与并发流程

1. Worker 在线验证身份，忽略或拒绝客户端 owner、模拟日期、经验和整包状态；解析并严格校验命令封套。
2. 通过原子初始化事务保证账户行及唯一独立区存在。owner 主键与独立区部分唯一索引防止重复初始化，不覆盖已有数据。
3. 写入事务首先锁定 adventure_accounts 的当前 owner 行 FOR UPDATE。全部普通写入遵守相同入口与锁顺序；不能在 Handler 中逐表独立提交。
4. 在锁内先查 adventure_command_receipts。相同 owner／request_id 与 hash 返回原事实回执及当前投影；异 hash 拒绝。已成功重试不重做动作，也不因跨日再次判断原动作能否执行。
5. 新命令核对 expectedVersion 与 accounts.revision；失配明确冲突，不自动重放用户意图。取得本次事务的权威时间，按 Asia/Shanghai 得到业务日期，不接受客户端日期。
6. 复用后端规则校验当前对象、历史锁定、候选目的、配额和具体输入；预览及能力不作为绕过校验的凭证。
7. 在同一事务内写入全部相关表；外键、CHECK、唯一索引及必要延迟外键共同校验，事务业务逻辑补齐跨行条件。
8. 校验后更新 revision+1 与 updated_at，插入包含稳定事实结果的成功回执，并从同一事务数据生成返回所需的成长结果与能力。提交失败全部回滚。
9. Worker 返回结果，前端按 revision 应用；旧响应不能覆盖新状态。网络超时是结果未知，只能使用原请求身份重试，不能声称已回滚或新建请求重复发奖。

请求摘要只包含严格校验及规范化后的命令，不包含 expectedVersion。回执只保存成功结果，不预提交一条 in-progress 记录，也不保存等级、成就或解锁状态。版本达到安全整数上限、锁等待或事务预算超限时明确拒绝，不部分完成操作。

本期仍采用账户级 revision，不因拆表改变为不同任务互不冲突。读／预览入口在短事务内对账户行取 FOR SHARE，再读取该账户多表；所有写入先取 FOR UPDATE，确保一次响应的事实、revision、统计和能力一致。不会把事务保持到用户确认，也不在持锁期间调用外部服务。

内部带行锁的读取／预览由后端 POST RPC 运行在允许行锁的事务中，不使用 READ ONLY／STABLE GET 调用；前端 HTTP 的读取形式不因此定稿。

## 主要业务操作

| 操作 | 关键校验与关系表变化 |
|---|---|
| 创建／改名普通主线 | 账户锁内检查在用 normal 少于五条；独立区不能再建、改 kind 或结束；只写当前主线，不建目标或奖励。 |
| 创建／编辑目标 | 手选在用主线或独立区，名称和标准有效；新目标 active、未聚焦，追加归属排序；编辑不自动达成。 |
| 聚焦／排序 | 账户锁内检查同归属 active 聚焦目标不超三个；只改目标字段和同组相对顺序，不影响执行或目标状态。 |
| 创建任务 | 新 adventure_tasks 及首次 arrangement 同事务插入，利用延迟外键检查 current_arrangement_id；任务 pending、不计奖。 |
| 编辑任务 | pending 且归属可操作，只更新当前名称／说明，不改安排或完成快照。 |
| 改期 | pending、目的日为今天或未来；追加不可变 arrangement，previous_arrangement_id 指向原当前安排，再更新任务指针，task_id 不变。 |
| 误建删除 | 尚未开始且从未产生完成、奖励或历史安排；设置 tasks.deleted_at，不物理删除或减少其他历史。 |
| 任务迁移 | pending、源／目的可操作；只更新当前 goal_id，安排和完成的历史归属列与快照不变。 |
| 目标迁移 | active、源／目的可操作、目的聚焦名额足够；更新 mainline_id 和目的排序位置，下属任务仍引用同一 goal_id，不改历史。 |

日期改动保留安排链；不能把已到执行日任务改到未来再当作误建删除。曾有已取消完成也算产生过记录。五条主线、三个聚焦等跨行规则在账户锁内校验，不能用含当前日期或跨表查询的普通 CHECK 假装约束。

### 完成任务

检查任务 pending、未删除、当前安排日期为 today，当前目标及主线可操作，无有效完成。生成新 completion_id，插入完成时 mainline_id／goal_id 和内容快照；插入关联该完成的 1 点 task 奖励；更新任务 completed 及 active_completion_id。

完成部分唯一索引阻止同 task_id 的第二条有效完成，来源唯一键阻止同 completion_id 的第二份奖励。任务当前完成指针的延迟复合外键保证 owner 和 task 一致；是否有效、是否当前安排及奖励同时存在由事务入口校验。

### 取消完成与重新完成

定位具体 completion_id，核对它属于任务、未删除且为 active_completion_id，完成日期为 today；检查任务、当前归属及完成时原主线／目标未终态锁定。

在同一事务中给该完成和对应 task 奖励设置相同 deleted_at，任务回到 pending 并清空 active_completion_id。数据库保留旧行，不追加负数冲正；等级、成就按剩余有效事实实时投影。

重新完成使用新的 completion_id 和 reward_id。旧成功 key 重试返回原回执；新 key 若仍指向旧完成也须拒绝，不能取消后来完成。对应任务奖励不能按 task_id 模糊删除，必须通过 completion_id 精确定位。

### 目标达成与奖励

目标 active，当前主线可操作；使用与预览一致的 revision。根据 completions 中完成时 goal_id 查询有效完成，按稳定 task_id 去重得到 N；C 为所选 1／2／3，默认 1。

同事务内：插入唯一 goal_attainment，冻结评价和目标快照；把每个计奖行动写入 goal_reward_actions；插入引用 attainment 的 goal 奖励；将目标置 achieved 并取消聚焦；下属 pending 任务 ended，已完成任务保留 completed 并只读。

N>0 时奖励 N×C，N=0 时固定 1 点、不乘系数。action_count 必须与计奖关联行数一致；关联表复合外键保证目标和历史完成归属一致，owner／task 唯一键防同一行动参与多个目标奖励。达成不增加行动数，无任务或仍有未完成任务也可按标准达成，不补造任务。

目标已达成后不恢复、迁移、改评价或撤销奖励。当前任务迁出不带走旧计奖行动，迁入不补记旧行动；目标本身迁移保留 ID，历史 mainline_id 仍不改。

### 结束与历史锁定

- 手动结束 pending 任务：设置 ended 状态、时间和原因，安排历史保留；completed 不改成未完成而结束。
- 结束目标：退出聚焦，停止当前下属 pending 任务，已有 completed、完成及奖励保留且只读。
- 结束普通主线：当前 active 目标进入 ended，已有 achieved 不改；下属 pending 停止，已有成果保留。独立区不能结束。
- 传播只沿当前归属；迁出目标或任务不随原主线结束，但原主线下历史完成仍不能撤销。不要把旧安排的历史锁定用于阻止当前合法新行动。
- 空容器、下属全部完成／结束／迁出，不自动结束上级；结束不发奖、不补发未执行行动。

## 能力、预览及成长读取

前端所需能力、原因、候选归属、合法输入范围、奖励预览及终态影响由后端返回。读取和提交复用后端规则函数，不能在 Worker、浏览器或 SQL 分别维护三套规则。

能力绑定 revision 和规划日期；同版本跨日也可能失效。预览不保存业务事实，最终命令重新校验；预览后版本变化必须重新读取并确认，不能静默改奖励金额。

按 owner 及有效标记查询：总经验 SUM(rewards.amount)，行动数为未删除完成的稳定 task 数，目标数为 achieved 目标数。等级和七个成就实时计算并返回，不持久保存到表、回执或缓存事实。聚合统计基于全部有效行，列表按稳定日期＋ID 游标分页，不能用当前页重算统计。

读取刷新不生成奖励或成功命令回执；首次账户初始化例外。任务汇总分母、已结束任务统计、终态显示及独立任务筛选仍待确认；完整 HTTP 字段、错误结构和预览传递方式在接口定义阶段确定。

## 必须覆盖的设计验收

| 场景 | 预期 |
|---|---|
| 同账户并发初始化 | 只有一条账户元数据、一个独立区，其他行不被覆盖 |
| 跨 owner 串入已有实体 ID | 复合外键或事务校验拒绝，不能仅依赖前端候选过滤 |
| 同任务并发完成 | 仅一条有效完成、一份任务奖励；账户 revision 冲突及部分唯一索引均有验证 |
| 取消 A、重新完成 B，再重试取消 A | B 保持有效，旧请求不撤回新完成 |
| 达成时记录、奖励、关联或停止任务写入失败 | 整个事务回滚，不能留下半达成或半奖励 |
| 目标计奖引用错误目标／独立任务／重复行动 | 复合外键、唯一键或事务规则拒绝 |
| 改期及迁移后完成 | task_id 稳定，日期和归属历史不改写，单次奖励不重复 |
| 取消与达成并发 | 账户锁决定顺序：取消先成功则旧预览失效，达成先成功则取消被终态锁定 |
| 多表读与写并发 | 一次读取的 revision、能力、事实和统计一致，不混用不同版本 |
| 新命令跨日／成功 key 跨日重试 | 新动作按本次权威日期校验；成功 key 只返回既有事实回执 |
| 事务超时／响应丢失 | 明确拒绝与结果未知区分；原 key 重试不重复发奖 |
| 19→20→19 经验及多页流水 | 等级、成就按全量有效事实实时变化，分页不截断统计 |

本次只设计，没有执行建表、函数、迁移、权限或数据库／接口／并发测试。旧单表 CAS 与浏览器证据不能证明本关系表事务设计已经通过。

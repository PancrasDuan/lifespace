# 后端业务逻辑设计

状态：2026-10-20 设计稿，供评审，暂不实现。依据 [领域规格](spec.md)、[成长与奖励](growth-rewards.md)、[前端设计](decisions-frontend.md) 和 [数据库设计](backend-database.md)；本文件定义业务处理，不提前确定完整 HTTP 请求／响应结构。

## 模块职责

| Module | 负责的行为 | Interface 与约束 |
|---|---|---|
| 请求处理 | 在线验证账户及准入、严格输入校验、服务端时钟、幂等与版本控制、组织响应 | 不接受客户端 owner、模拟日期、经验、整包 state 或自行计算的奖励 |
| 领域 Module | 命令校验与执行、归属／终态／历史不变量、能力与影响预览、成长实时投影 | 同一套后端规则供提交和预览使用，不发送给浏览器重算业务；输入不直接修改，失败不产生部分状态 |
| 存储 Module | 按已验证 owner 读取、首次初始化、带旧 version 的 CAS 写入 | 沿用现有 PostgREST Adapter；持久提交包含全部事实和 journal，不分开提交完成与奖励 |

领域命令是主要测试 Seam，存储 Adapter 的账户隔离和 CAS、HTTP 的身份及错误语义分别验收。不为本期额外引入事件总线、后台结算任务或通用 CRUD 体系。

## 统一命令流程

1. 在线验证会话和准入，确定 owner；严格校验命令字段。进入业务处理时取得一次权威 now 及 Asia/Shanghai today，供本次处理统一使用。
2. 读取当前账户聚合，空账户按 owner 主键安全初始化唯一独立区和空集合；初始化冲突不能覆盖已有行。校验内部 schema 和必要引用，结构不支持时明确拒绝。
3. 先查 `request:<requestId>`。同 key 同摘要直接返回原业务回执与当前读取版本的实时投影；同 key 异摘要拒绝。已成功操作的重试不再次检查“今天还能否操作”并重做动作。
4. 未执行过的新命令核对 expectedVersion。失配即冲突，先读取并由用户重新确认；不静默按更新后的数据重放意图。
5. 用当前聚合和服务端日期校验对象、归属、配额、历史锁定、具体输入及前置条件。能力或预览只作展示参考，提交不能跳过此步骤。
6. 在候选副本上应用全部变化；校验引用、有效完成唯一性、奖励对应、终态传播和容量。生成只含业务事实的稳定回执，加入候选 journal。
7. 一次条件写入：owner_id 相同且旧 version 相同才保存 state、journal、version+1 和 updated_at。普通业务命令 CAS 失败不自动重新执行。
8. CAS 未命中时只读最新行：若同 key 同摘要已成功则返回其回执，否则返回版本冲突或 key 复用错误；不得用最后写覆盖。
9. 成功后按已保存版本生成能力、预览所需基础事实和成长投影，并返回稳定结果。客户端按版本应用，不能让旧响应覆盖新状态。

明确业务拒绝不写入候选；网络超时则是结果未知，可能已经整体提交。只允许使用原请求身份重试确认，不把超时解释为已回滚，不新建请求重复发奖。version 达到安全整数上限或候选超容量时拒绝写入，仍允许读取原状态。

读取、刷新与预览不产生新奖励、不补发历史，也不为刷新写一笔业务 journal；只有无账户行时允许安全初始化。任何原有周期 refresh／次日结算流程都不是本期行为。

## 业务命令及原子变化

| 操作 | 前置条件 | 同次提交的事实 |
|---|---|---|
| 创建普通主线 | 在用普通主线少于五条，名称有效 | 新主线 active；不自动建立目标或发奖 |
| 修改主线名称 | 普通主线 active | 当前名称变更，历史快照不改 |
| 创建目标 | 名称、标准有效，手选在用主线或独立区 | 新目标 active、未聚焦，追加当前归属排序，不自动建任务 |
| 编辑目标 | 目标及当前主线可操作 | 只改名称／标准，不自动达成 |
| 聚焦／排序 | 目标 active，聚焦目的名额足够；排序只涉及同归属同展示组的可操作目标 | 修改聚焦或组内顺序，不改变执行、达成或其他组的相对顺序 |
| 创建一次性任务 | 手选可操作目标或独立身份，执行日为今天或未来 | 一个稳定 taskId、一条首次安排，状态 pending，无奖励 |
| 编辑任务内容 | pending 且当前归属可操作 | 更新当前名称／说明；已有安排或完成快照不改 |
| 改期／重新安排 | pending，源与当前归属可操作，目的日为今天或未来 | 追加关联原安排的新记录，切换 currentArrangementId；taskId 不变，不产生新行动或奖励 |
| 误建删除 | pending、尚未到首次执行日、无任何完成／奖励记录或历史安排 | 任务设置 deletedAt，保留数据库记录，从有效列表排除，无奖励 |
| 任务迁移 | pending、源与目的均可操作，目的为目标或独立身份 | 更新当前 goalId，保留任务身份、安排与状态；不改历史快照 |
| 目标迁移 | 目标 active，源／目的可操作，保留聚焦时目的名额足够 | 修改 mainlineId，任务随同一 goalId，落位目的同类组末尾，历史不重写 |

“曾产生过完成／奖励”包括已逻辑删除记录，不能通过取消完成恢复误建删除资格。日期改动一律追加安排历史，不能把已到执行日的任务改到未来后再当成未开始误建任务删除。

### 完成任务

检查任务 pending、未删除、当前安排日期为 today、当前归属可操作，且没有有效完成。历史旧安排的归属不锁定迁移后的合法新行动。

同次提交：创建新完成 ID 及发生时快照；任务改 completed 并关联该完成；创建引用该完成 ID 的 1 点奖励。总经验、等级与成就从候选有效事实计算，但不保存为新状态。

同一行动只按稳定 taskId 计一次。重复点击、相同 key 重试和不同 key 并发均不能产生第二条有效完成／奖励；版本赢家以外的请求需返回当前结果或明确冲突。

### 取消完成

命令必须定位具体完成 ID。检查它仍有效、属于该任务且等于任务 activeCompletionId，完成日期为 today；任务、当前归属及完成快照中原目标／原主线均未终态锁定。

同次提交：该完成与它对应的任务奖励设置相同 deletedAt；任务回到 pending，清空 activeCompletionId，原当前安排保留。经验与成就按剩余事实实时计算，不追加负数奖励或单独的降级／撤成就记录。

重新完成创建新完成与奖励 ID。指向旧完成的取消请求，即使使用新 requestId，也不能取消后来形成的新完成；旧成功 key 的重试只返回原回执。过去记录或上级终态不能通过迁移、改期或重发请求绕过。

### 达成目标

检查目标 active、当前主线可操作，确认来自与预览一致的版本；不以任务全部完成为门槛。按完成时 goalId 查有效完成并按 taskId 去重得到 N，系数 C 为 1／2／3、默认 1。

同次提交：goal.status=achieved、退出聚焦、记录达成事实；奖励为 N>0 时 N×C、N=0 时固定 1；冻结完成 ID 列表、N、C、可选感想和目标来源快照；下属 pending 任务进入 ended，completed 任务保留完成状态但被上级终态锁定。

不增加行动数，不创建空任务来表达保底奖励；目标成就只增加一个已达成目标。达成不可撤销，不提供事后修改评价、奖励或计奖依据。无当前任务但存在迁出的历史有效行动时，仍按历史 N 计算，不能误用保底。

### 结束与终态传播

- 手动结束 pending 任务：状态 ended，记录时间与原因，禁止恢复；安排历史不改写，不发奖。已完成任务不能改成未完成而结束。
- 目标未达成而结束：目标 ended、取消聚焦，下属 pending 任务 ended；completed 与已有奖励保留并只读。
- 结束普通主线：主线 ended；当前归属下 active 目标进入 ended，achieved 结果不改；下属 pending 任务停止，已有完成及奖励保留。固定独立区不能结束。
- 传播只作用于当前归属树。已迁出的进行中目标或任务不随原归属结束，但原归属下历史完成仍按其快照保持撤销锁定。
- 空容器、下属全部完成／结束／迁出，不自动改变上级状态。结束不额外发奖，不补发未执行行动；本期无待入账的一次性奖励。

## 读取、能力与影响预览

领域 Module 在后端从同一聚合版本构建页面数据：当前对象、历史内容、允许操作和原因、候选归属、输入范围、排序及统计。能力使用与正式提交相同的后端业务规则，避免在浏览器复制规则。

单次请求只按 owner 读取聚合，构建并复用请求内的实体／有效完成索引；不为每个按钮重新查询数据库或克隆完整历史。临时索引不跨账户、跨请求缓存，不能产生另一份持久化事实。

对象级允许操作不能代表所有输入合法；迁移目的、日期、聚焦目的配额等要单独判定。能力应绑定版本及规划日期；即使版本未变化，跨日后能力也可能失效，最终命令仍按权威日期校验。

预览结果不持久化，也不接受客户端回传“计算后的状态”作为事实；无账户行时的安全初始化是唯一例外，不保存预览本身。达成预览给出计奖依据和各档奖励或支持按选择重取预览；取消、结束、删除预览给出受影响对象、经验及成长变化和确认需求。预览后版本变化必须重新读取并确认，不能静默改变奖励。

任务汇总范围、分母、已结束任务口径、终态显示及独立任务筛选尚未确定；先保证底层事实完整，不能将原型默认行为写成业务规则。完整 HTTP 字段、端点、错误结构及预览传递形式在下一阶段定义。

## 成长投影

- 有效奖励求和得总经验；等级按逐级 20+5×(当前等级−1) 计算，本级进度及距升级经验均在后端返回。
- 有效完成按稳定 taskId 去重得行动数，状态 achieved 的目标计目标数；生成行动 1／10／50／100 和目标 1／3／10 七个里程碑的满足情况、进度与差额。
- 不保存等级、成就、解锁／撤回状态或解锁日期，包括成功命令 journal 内也不保存一份历史成长状态；前端只格式化服务端结果。
- 有效流水排除逻辑删除奖励，来源取发生时不可变快照。全量统计先于分页，不能用当前页或当前任务归属重算历史计奖。
- 取消可使等级回退、成就不再满足；重试只读回当前结果，不重复产生奖励或额外解锁事实。

## 必须覆盖的设计验收

| 场景 | 预期 |
|---|---|
| 两次首次读取并发初始化 | owner 主键只保留一行及一个独立区，已有数据不被覆盖 |
| 两设备同版本完成同任务 | 只有一条有效完成与 1 点奖励；其他请求明确重试结果或冲突 |
| 取消完成 A、重新完成 B，再重试取消 A | B 仍有效；原 key 仅返回回执，新 key 指向无效 A 也不能取消 B |
| 改期多次后完成 | taskId 不变，仅当前安排可完成；过去安排内容和来源保留，单次奖励不重复 |
| 无任务目标或 N=0 的目标达成 | 固定 1 点，目标数增一，行动数不增加 |
| 完成迁入前的历史行动 | 不转计新目标；目标自身迁移保留 goalId 下的历史计奖，原主线快照不改 |
| 目标迁出后原主线结束 | 迁出目标仍可推进；原主线历史完成不可取消，不锁死其新的合法行动 |
| 取消与达成并发 | 取消先成功则旧达成预览失效；达成先成功则取消被终态锁定 |
| 新命令跨日与成功请求跨日重试 | 新命令按服务端日期校验；成功 key 重试不重做动作或再次发奖 |
| 终态时有已完成和未完成任务 | 完成事实／奖励保留，未完成停止，退出聚焦，全部只读 |
| 容量超限、无效引用、无权 owner、旧 schema | 明确拒绝，不能静默修复、覆盖原数据或裁剪幂等事实 |
| 全局 19→20→19 经验及多页流水 | 等级和七个成就按全量有效事实实时变化，分页不截断统计 |

本次仅完成设计。以上是后续实现的验收要求，没有执行数据库、接口或并发测试，不用既有旧版测试冒充新规则已通过。

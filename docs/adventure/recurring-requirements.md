## 已确认需求

| 编号 | 需求 | 具体含义 |
|---|---|---|
| R01 | 周期内自由完成 | 设置每周期要求次数，不提前指定每次执行日期。例如每周刷 LeetCode 5 道题，可以在不同日期或同一天完成多道，按每次真实行动分别记录。固定日期重复和一次性任务分多日执行尚未确认为本轮范围。 |
| R02 | 周期种类 | 首期支持周、月、季、年；本轮不加入每日周期。 |
| R03 | 按指定开始日划分周期 | 开始日为锚点，包含开始当天，每期结束于下一期开始前一天。周为连续 7 天，月为 1 个月，季为 3 个月，年为 12 个月；不按自然周、自然月或自然季度另切边界。 |
| R04 | 开始后保留原始锚点 | 月末或闰日对应日期不存在时，临时取目标月份最后一天，后续仍沿用原始锚点。例如月周期 1 月 31 日 → 2 月 28／29 日 → 3 月 31 日；闰日年周期平年取 2 月 28 日，闰年回到 2 月 29 日。尚未开始时修改开始日期按 R17 处理。 |
| R05 | 新增完成受当前要求次数限制 | 不允许超额新增完成：本期有效完成次数达到或超过当前要求次数时，不能继续新增完成记录。要求仍为 5 次时，达到 5/5 后不能记录第 6 次。次数下调导致已有完成数超过新要求时，按 R13 保留事实，不追删明细。 |
| R06 | 未完成次数不结转 | 某期只完成 3/5，下一期仍从 0/5 开始，不累加成 7 次要求；原来 3 次真实完成数据保留。 |
| R07 | 保留完成明细，进度通过计算获取 | 保留每个周期每次完成的数据，能够确定实际完成日期及所属周期、周期序号。父任务不保存任务进度值，也不单独保存每期进度快照；进度通过计算获取，后续可按完成明细聚合统计，不因周期结束清除完成事实。父任务层面另提供 R28 的两种周期计数，其中完成周期数按 R29 保存，不将计数混同于本期任务进度。 |
| R08 | 当前周期数表示第几期 | “当前周期数”与“周期序号”同义，表达第 1 期、第 2 期等；“完成周期数”另指满足整期要求的周期数量，见 R28。未完成要求也会随周期边界进入下一期；次数调整不改变当前周期数。 |
| R09 | 按实际操作当天记录 | 不允许补记，完成计入实际操作当天所在周期；不能回填到上一期或预记到下一期。日期统一按 R38 的北京时间判断，跨天新写请求按 R40 拦截并提示刷新。 |
| R10 | 完成当天可撤销 | 任务仍可操作时，可撤销当天的具体一条完成记录，使本期有效完成次数减少 1，例如 5/5 恢复为 4/5；是否可继续新增仍按 R05 判断，跨日后不能撤销。子任务失效方式见 R27；父任务结束或完成时所属目标终态的只读锁定优先，见 R19／R33。 |
| R11 | 周期类型创建后固定 | 为简化本轮范围，任务创建后不能在周、月、季、年之间切换，不提供周期类型修改。开始日期按 R16／R17 处理，不因周期类型固定而禁止尚未开始时修改开始日期。 |
| R12 | 次数调整当期生效 | 允许修改每期要求次数，修改保存后立即应用于当前期，不等待下一期。次数调整不改变已有完成明细、周期长度、当期起止日期或周期序号；下调与后续期的适用范围分别见 R13／R14。 |
| R13 | 下调不受已完成次数约束 | 用户拒绝“不得低于本期已完成次数”的限制。已完成 4 次时可把要求从 5 次改为 3 次，原 4 次真实完成保留；此时不能继续新增，除非以后调整要求或撤销当天记录，使有效完成数低于要求。下调仍须满足 R15 的正整数要求。 |
| R14 | 次数调整持续生效 | 修改后的要求持续适用于后续各期，不是本期临时覆盖。例如从 5 次改为 7 次，本期立即采用 7 次要求，下一期从 0/7 开始。历史完成明细不改，已结束周期的结果按 R32 冻结，相关历史依据的具体保留方式仍待实现设计。 |
| R15 | 要求次数为正整数 | 次数必须为大于等于 1 的整数，不允许 0、负数或小数；创建与调整均遵循此规则。“下调不限制”仅指可低于已完成次数，不表示允许零要求。 |
| R16 | 创建时开始日只能选今天或未来 | 创建周期任务不允许把开始日期设为过去；开始日期以 R38 的北京时间规划日期判断，跨天操作不得借旧页面绕过日期及生命周期校验，见 R40。 |
| R17 | 开始日期仅在尚未开始时可改 | 尚未到开始日时，允许将开始日期改为今天或未来，以修改后的开始日作为周期锚点；从开始当天起固定，即使尚无完成记录也不再修改。周期类型仍遵循创建后固定的 R11。 |
| R18 | 首期不提供暂停／恢复 | 不提供暂停／恢复操作，周期按既定日期连续推进；不采用旧待办中暂停冻结与顺延周期的规则。 |
| R19 | 手动结束且不可恢复 | 允许手动结束，立即停止新增完成，不必等到本期结束；整条任务及已有完成明细只读保留，不可恢复。结束后不能继续编辑或撤销当天完成，不清除已有完成事实或对应有效奖励，也不额外发放结束奖励；目标终态前处理见 R24，历史归属锁定见 R33。 |
| R20 | 首期不设置计划结束日期 | 只提供手动结束，不增加计划结束日期或按计划日期自动结束；完成当期要求也不会自动结束整条周期任务。 |
| R21 | 只有未开始的周期任务可删除 | 删除资格按是否已经开始判断，不按有效完成记录是否为零判断。仅未开始状态可删除；从开始当天起，即使从未完成或当天完成已全部撤销，也不能删除，只能结束。已结束任务继续只读，不因原开始日仍在未来而允许删除。 |
| R22 | 归属目标或独立存在 | 周期任务可以属于一个进行中目标，也可以不依附任何目标、作为独立任务。目标是唯一主结构，不恢复主线；目标终态前处理见 R24，迁移见 R26。 |
| R23 | 未开始或运行中可编辑内容 | 允许编辑名称、说明和要求次数；已发生的完成保留发生时内容，不随当前编辑改写。未开始时调整次数，首次开始即使用调整后的要求；运行中按 R12 当期生效并按 R14 持续生效。周期类型和开始日期仍分别遵循 R11／R17，结束后只读。 |
| R24 | 目标进入终态前先处理周期任务 | 目标达成／结束前必须先处理该目标下所有未结束的周期任务，包括未开始或本期已达到要求的任务；系统不自动结束它们。已经结束的周期任务和已有完成事实保留，不因目标进入终态清除。 |
| R25 | 周期父任务与完成子任务 | 周期任务作为父任务，每次真实完成形成一条关联父任务的周期子任务数据。子任务主要保存该次完成发生时的父任务快照及子任务独有信息；“父任务完成时”指记录一次行动完成的时点，不指整条周期任务最终结束。具体快照和子任务字段清单仍待细化。 |
| R26 | 父任务可迁移，子任务不迁移 | 未结束的父任务可在进行中目标或独立身份之间迁移，包括跨目标。保持父任务身份、周期锚点、期数及当前期完成连续；原子任务的内容与完成时目标归属固定、不可迁移，新完成子任务采用迁移后的归属。进度始终以同一父任务为统计对象，不因迁移清零。 |
| R27 | 撤销使子任务失效 | 保留当天撤销：撤销具体子任务的完成后，该子任务从有效统计排除、父任务本期有效完成次数减少 1，子任务原内容与归属保留，不恢复为待办子任务。可撤销日期与只读条件遵循 R10／R19／R33。 |
| R28 | 父任务层面提供两种周期计数 | 当前周期数表示当前是该任务第几期，完成周期数表示已有多少个周期 100% 完成；后者不是本期已完成次数，也不是所有已结束周期数。此定义取代本轮早先将“完成周期数”解释为第几期的用法。完成周期数存储方式见 R29，当前期计入与回退见 R30／R31，历史周期冻结见 R32。 |
| R29 | 保存完成周期数 | 用户比较记录计数与查询聚合后，选择保存完成周期数，认为本轮记录计数的成本更低；不采用每次查询重新按全部历史明细及要求变化聚合的方案。该选择不改变进度计算获取、保留子任务快照的规则，不表示已经决定具体字段或增加每期进度记录。 |
| R30 | 当前期满足情况实时维护完成周期数 | 当期从不满足要求变为满足时，完成周期数加 1；当天撤销或上调要求导致本期从满足变为不足时减 1。每期最多贡献 1，反复撤销／完成不累加多份，满足状态不变时计数不变；不等待周期结束才计入。 |
| R31 | 有效完成数大于等于要求即满足 | 本期有效完成次数大于等于当前要求次数即视为该期 100% 完成。下调要求导致 4/5 变成 4/3 时也算满足；若该期此前未计入，完成周期数加 1，全部原完成明细保留。不借此允许在已满足要求时新增完成；进度具体呈现仍在界面分支讨论。 |
| R32 | 已结束周期结果冻结 | 周期结束后，该期是否满足要求的结果固定，后续修改要求只影响当前及未来，不重算过去对完成周期数的贡献。例如上期按 5/5 完成，本期改为要求 10 次，上期仍贡献 1 个完成周期；不因此新增逐期进度快照。 |
| R33 | 完成时目标终态锁定 | 子任务完成时所属目标已经达成或结束后，禁止再撤销该子任务，即使仍是完成当天。父任务迁入其他目标或转为独立任务，不会解除原归属目标的只读锁定。 |
| R34 | 每个有效子任务实时奖励并计一次行动 | 每个有效周期子任务实时获得 1 点经验、计为 1 次行动，合法撤销时对应奖励及行动计数同步回退；父任务不重复计算同一次行动。沿用现行一次性任务的事实与奖励原子提交、取消后逻辑失效及不追加负数冲正规则。 |
| R35 | 首期没有整期额外经验 | 本期满足要求或完成周期数增加，不额外发放经验；完成周期数仅作统计。不因下调要求、父任务编辑／迁移／结束等没有新增真实行动的操作发放额外经验；有效子任务的既有经验不因这些操作扣减。 |
| R36 | 子任务参与目标达成计奖 | 每个有效周期子任务按完成时所属目标计入一次计奖行动，与该目标有效一次性任务完成共同组成 N；父任务与完成周期数不额外计入。目标奖励沿用 N>0 时 N×成就系数、N=0 时固定 1 点的公式，系数仍为 1／2／3。父任务迁出不带走旧子任务的历史计奖归属，迁入不补记旧独立子任务。 |
| R37 | 目标总进度与周期进度分开 | 目标总进度只统计原有一次性任务，不把周期父任务或周期子任务混入该进度的完成数与分母。周期任务单独在父任务上展示本期进度。目标计奖行动数仍按 R36 包括有效子任务；目标任务数见 R50；相关任务列表与其余界面布局另行确定。 |
| R38 | 统一北京时间规划日期 | 周期边界、开始日期及当天撤销统一按服务端 Asia/Shanghai（北京时间）的日期判断，沿用现行人生冒险规划时区，不随设备或首页地区变化。实际完成时间由系统记录，不由使用者指定过去或未来日期。 |
| R39 | 首期不提供子任务备注 | 用户在原型复核时撤回原先选填备注的方案。本期移除每次完成的备注输入、展示和事后编辑，不另填子任务名称。父任务通用说明保留；父任务快照、父子关联、期数、实际完成时间及完成时归属由系统记录。 |
| R40 | 跨天拦截后前端提示刷新 | 对记录完成、调整次数等依赖规划日期的周期操作，若新写请求所依据的日期已跨天，服务端拦截、不执行业务写入，由前端提示并刷新权威日期、期数及能力；刷新不自动补交，后续须由用户再次主动操作。北京时间日界也覆盖自然跨期。已经成功的旧请求仍按原回执重放，不重复生成子任务、发奖或改变计数。 |
| R41 | 今日单独展示运行中父任务 | 查看今天时单独显示周期任务区域，每个运行中的父任务一行，展示本期进度、当前期数和完成周期数。本期达到或超过要求后仍保留展示，但禁用“记录一次”；父任务仍可按既定规则查看或编辑要求，不因当期满额视为整条任务结束。 |
| R42 | 直接记录一次完成 | 点击“记录一次”直接提交，不再打开备注录入或确认弹窗。以更新的本期进度、当天完成条目和简短成功反馈表示结果；误操作按当天撤销规则处理。发出请求后的成功／未知结果继续沿用原请求与回执恢复规则，同一请求不重复记录或发奖。 |
| R43 | 子任务按实际完成日展示 | 周期子任务按实际完成日期进入今日已完成及过去日期列表，可展开查看完成时名称、时间、期数与归属快照，并按服务端能力在允许的当天撤销；首期无本次备注。父任务继续留在周期区更新进度。子任务不会成为另一条待办，不预建未来待办子任务；今日进度按 R44 计入有效子任务。 |
| R44 | 今日进度计入当天有效子任务 | 今日已完成为今天有效一次性完成加今天有效周期子任务；今日总数为今日已完成加逾期待完成及今日待完成的一次性任务。父任务及本期剩余要求次数不加入分母。例如一次性 2 完成、1 待办，再完成 2 个子任务，今日进度为 4/5。此口径与仅统计一次性任务的目标总进度 R37 区分。 |
| R45 | 一次性与周期任务统一管理 | 用户建议与一次性任务合在一起管理，不采用独立“管理周期任务”入口。用户进一步指定统一按日期管理，见 R46；列表对象、状态归属及布局细节继续讨论，不推翻 R41 的今日独立周期区，也不授权新增顶级导航。 |
| R46 | 统一按日期管理 | 用户明确“统一按照日期管理”：沿用现有周历／日期入口管理一次性与周期任务，不增加独立的“任务管理”切换，也不继续 A／B／C 独立管理布局。R41 的今日周期区和 R43 的实际完成日明细继续适用；未开始父任务的开始日归属和已结束父任务的结束日归属已按 R47／R48 确认；运行中父任务仅今天展示，见 R49。 |
| R47 | 未开始父任务放在开始日 | 用户确认未开始的周期父任务显示在其开始日，选中该日期即可编辑或删除。选择未来开始日只改变查看日期，不使任务提前开始，不允许预记完成。修改开始日后，入口随新开始日移动；删除仍按 R21 的真实开始状态判断。 |
| R48 | 已结束父任务放在结束日 | 用户确认已结束的周期父任务在结束日保留只读条目，不允许编辑、删除、恢复或新增完成；每个子任务仍按实际完成日查看，不因父任务结束把所有明细移到结束日。结束条目不重复计入今日进度、经验或行动数。 |
| R49 | 运行中父任务首期只在今天展示 | 用户确认已开始且未结束的周期父任务首期只在今天显示。历史日期查看实际完成与结束条目；未来日期保留未开始任务的开始日入口，不展开运行中任务的未来周期计划。选择日期不改变真实规划日期、当前周期或操作能力。 |

| R50 | 目标任务数按任务对象计数 | 用户确认目标任务数包含当前归属的一次性任务（待完成及已完成）和未结束周期父任务（含未开始、本期已满额），周期子任务不重复计数，已结束周期父任务不计入。迁出、结束或删除父任务后相应减少当前目标任务数，不改写旧子任务归属。目标总进度仍只统计一次性任务。例如 2 个一次性任务（1 个完成）加 1 个未结束周期父任务，任务数为 3，一次性进度为 1/2。 |
| R51 | 用界面状态引导操作 | 用户要求以设计语言引导：用进度、满额按钮状态、锁图标及只读值表达能力和规则；削减重复说明，不移除必要字段标签、错误恢复信息、结束不可恢复等关键后果。只调整已授权原型区域，不扩大外围改版。 |

## 已确认规则的场景核对

以下用于核对讨论含义，尚不构成完整实施验收清单。

- 周三开始的周周期包含周三至下周二，下周三进入下一期；不在周一重置。
- 一期要求 5 次，记录 3 次后到期：新一期为 0/5，先前 3 次明细仍能归属原期。
- 一期达到 5/5 且要求仍为 5：不能新增第 6 次；当天撤销其中一条后为 4/5，可重新记录一次真实完成。
- 一条完成的实际操作日过去后，即使仍在同一期内，也不能补记或撤销该条过去完成。
- 每期要求 5 次，第 1 期完成 5 次、第 2 期完成 3 次：下一期当前周期数为 3，完成周期数为 1，不把周期序号当作完成周期数量。
- 本期进度为 3/5，将要求调整为 7 次后，本期立即变为 3/7，周期起止日期、期数与原来 3 次完成明细不变。
- 本期已完成 4 次、原要求为 5 次：允许将要求降至 3 次，保留全部 4 次完成明细，停止新增完成；具体进度呈现留待界面讨论。
- 本期已完成 5/5，将要求提高至 7 次：按即时生效及当前次数限制规则，本期成为 5/7，可继续记录至 7 次；下一期从 0/7 开始。
- 创建为周周期的任务不能改为月周期；本轮不再讨论周期类型变更当期或下期生效。
- 要求次数设为 0、负数或小数时不能保存；即使本期已完成 4 次，仍可把要求降为 1 次并保留全部 4 次完成事实。
- 今天创建时，开始日不能选择昨天；若选择未来日期，在任务尚未开始时可以重新安排开始日。
- 一条未来开始的周周期任务，在开始前可将开始日改为今天，但不能改为月周期；开始日到来后即使仍为 0 次完成，也不能再改开始日期。
- 本期已完成 3/5 时可以手动结束，不补成 5 次、不删除原 3 次明细；结束后不可恢复，也不能再编辑任务或撤销当天记录。
- 一段时间没有执行，不会暂停或顺延周期；下一期仍按既定边界开始。
- 开始日仍在未来且任务未结束时可以删除；到达开始当天，即使完成数为 0，也不能再删除。
- 已开始任务当天完成后全部撤销，仍然不能删除；需要停止执行时使用结束。
- 完成本期全部要求后等待下一期继续，不自动结束任务；新建不提供计划结束日期。
- 可以创建某个进行中目标下的周期任务，也可创建独立周期任务；不要求先创建目标。
- 尚未开始时将要求从 5 次改为 7 次，开始当天按 0/7 计；运行中改名或修改说明后，原完成明细仍保留发生时的内容。
- 目标下有未结束周期任务时，即使该任务本期已达到 5/5，也不能直接达成／结束目标；必须先处理该周期任务。
- 同一期在目标 A 下完成 2 次，父任务迁入 B 后完成 1 次：计算所得父任务进度为 3/5，原两条子任务仍归 A，新子任务归 B。
- 父任务仍可操作时，当天撤销其中一条完成：该子任务从有效统计失效，原快照保留，父任务本期有效次数减少 1；不会新增一条待办子任务。
- 每期要求 5 次，前三期分别为 5/5、2/5、5/5，当前第 4 期为 2/5：父任务当前周期数为 4，完成周期数为 2；本期完成次数 2 是另一种统计。
- 同一期内从 4/5 完成至 5/5，完成周期数立即加 1；此时当前周期数不变，不提前进入下一期。
- 同一期内 5/5 当天撤销成 4/5，或将要求提高成为 5/6，完成周期数减 1；再次满足时恢复加 1，不重复累计同一期。
- 同一期内 4/5 下调要求成为 4/3，若此前未计入完成周期数则加 1；若随后当天撤销成为 3/3，仍满足、计数不变，继续撤销成为 2/3 时才减 1。
- 上期按要求 5 次完成 5 次并计入 1 个完成周期，本期改为要求 10 次：上期贡献保持 1，不按新要求重新变为未完成。
- 父任务从 A 迁入 B 后，A 达成／结束：归 A 的子任务即使完成于今天也不能撤销；归属 B 的子任务仍按自身日期及相关只读条件判断。
- 完成 1 个有效子任务，经验加 1、行动数加 1；合法撤销后两者各减 1，原子任务快照保留但不参与有效统计。
- 已有 4 个有效子任务，将要求从 5 降为 3：完成周期数可加 1，但经验与行动数仍各为这 4 次行动的贡献，不因整期满足额外增加。
- 4/3 当天合法撤销成为 3/3：完成周期数不变，经验及行动数各回退 1；手动结束父任务不额外发奖，也不撤销仍有效子任务的经验。
- 目标 A 有 2 个有效一次性完成和 3 个完成时归属 A 的有效子任务，计奖行动数 N 为 5；选择系数 2 时目标奖励为 10 点，不再为父任务或完成周期数多计行动。
- 目标 A 当前有 2 个已完成与 1 个待完成的一次性任务，以及一条本期 3/5 的周期任务：目标总进度为 2/3，周期父任务单独显示 3/5，既有子任务不把目标分母或完成数再增加。
- 设备或首页地区切换到其他时区，周期边界及当天撤销窗口仍按北京时间；选择历史日期不能把新完成回填到那天。
- 首期点击“记录一次”即可完成，不出现备注输入或确认弹窗；完成条目保留系统快照、期数及时间，父任务通用说明保留。
- 页面仍依据昨天的日期提交一次周期完成，服务端拦截且不产生子任务、奖励或新计数，前端提示并刷新；不能刷新后自动把原意图记入今天。若原请求昨天已经成功，仍只返回原回执。
- 查看今天时，一条本期 5/5 的运行中父任务仍显示在周期任务区，“记录一次”不可用；把要求提高为 7 后，权威结果为 5/7，可按能力继续记录。
- 单击记录后进度与当天完成同步更新，误操作可按当天撤销规则回退；通过 URL 打开页面不会自动记录。
- 父任务原为 2/5，今天点击记录一次后，今日已完成增加一条子任务，父任务仍显示并计算为 3/5；之后从过去日期可只读查看该天的子任务快照与期数。

## 已确认的父子模型与待澄清字段

用户提出父子模型后，已确认保留子任务当天撤销，并进一步明确父任务不保存任务进度、需要提供两种周期计数并保存完成周期数，子任务保存父任务快照及自身信息。R25–R33 记录逻辑模型、计数存储、历史冻结与只读边界；每次行动奖励、首期无整期额外经验、目标计奖及目标进度见 R34–R37。物理表、具体界面与整体实施方案仍未确认。

- 周期任务作为父任务，保存规则、当前归属及生命周期；作为周期进度的统计对象，但不把进度值作为独立事实持久化。
- 每次真实完成时，形成一条关联父任务的周期子任务数据，保存父任务在该次完成时的快照及子任务独有信息，能够识别所属周期与完成时归属。
- 已完成子任务的内容与完成时归属固定，不随父任务改名或迁移改变，子任务不可迁移。
- 父周期任务可以迁移；迁移后新完成的子任务归属于新目标，旧子任务仍归属于原目标，不因换目标重新累计本期次数。
- 当天撤销只使具体子任务的完成失效，不改写其原内容与归属，也不恢复为待办子任务。
- 例如父任务在目标 A 下完成 1 次，迁入目标 B 后再完成 1 次：两条子任务都关联同一父任务，分别保留 A／B 归属，父任务当期累计为 2 次。

### 父任务周期计数：含义与计入规则已确认

用户明确：“当前周期数指的是当前周期是该周期性任务的第几期；完成周期数是当前已经有多少个周期 100% 完成了。”以本次定义为准，取代早先混用两个名称的表述。

当前周期数、完成周期数、本期完成次数和每期要求次数是不同概念。前两者在父任务层面提供；用户已选择保存完成周期数，并确认当前期满足要求时实时计入、不再满足时回退，已结束周期结果固定。具体物理表示、跨期刷新与完整性校验仍待实现设计。

### 已确认取舍：保存完成周期数

用户在讨论查询聚合后明确选择记录完成期数，以控制本轮复杂度；完成周期数作为父任务层面的累计计数保存，进度仍通过计算获取。不采用每次查询按全部历史子任务及要求变化重算完成周期数的方案，也不因此增加逐期进度快照。

当前期采用 R30／R31 的实时维护规则，使完成、撤销和要求次数调整后的结果一致。同一周期内的计数变化等于“操作后是否满足要求（1／0）减去操作前是否满足要求（1／0）”；满足判断为有效完成数大于等于要求数。项目现有账户事务、操作事件、幂等与成功回执规则继续适用，计数维护需要与相关业务事实同次事务提交，旧成功请求重放不得再次改变计数。

此前讨论过的查询聚合方案依赖历史要求依据：完成 4 次、当时要求为 5，随后要求调为 3 且没有新完成时，子任务快照仍是要求 5。该例用于解释取舍，不作为本轮必须新增完整规则版本回算机制的要求；既有操作历史及子任务快照仍按各自约束保留。

当前周期数如何根据开始锚点与规划日期刷新、累计完成周期数如何校验，仍待实现设计；前端不得按当前列表页自行维护业务计数。

1. 今日进度已按 R44 确认；父任务及本期剩余次数不加入分母。
2. 统一按日期管理已按 R45／R46 确认，独立“任务管理”切换及 A／B／C 管理布局撤回；未开始父任务放开始日、已结束父任务放结束日已按 R47／R48 确认；运行中父任务首期只在今天显示已按 R49 确认。
3. 父任务快照与子任务独有信息的完整字段清单。
4. 目标任务数已按 R50 确认；目标相关任务列表的父子呈现仍待讨论，不直接套用任务数、进度或计奖口径。
5. 是否复用现有任务表、如何关联父子任务与完成事件、完成／撤销的事务与幂等身份，尚未决定。

### 已解决分支：修改规则何时生效

用户选择本轮简化：周期类型创建后固定，次数允许调整并当期生效，见 R11／R12。不再将“周期长度修改下一期生效”或“次数修改下一期生效”作为本轮候选要求。

首期只提供手动结束，不设置计划结束日期，见 R20。用户明确删除只适用于未开始的周期任务，见 R21；此前按“没有有效完成记录”判断删除资格的建议没有被接受。

周期任务可以归属一个进行中目标或独立存在，见 R22；未开始或运行中可以编辑名称、说明和要求次数，历史完成保留发生时内容，见 R23。迁移与目标终态前处理分别见 R26／R24。

### 已解决分支：目标终态前处理

用户明确目标进入终态前需要先处理周期任务，见 R24。可按已确认能力结束、迁出周期父任务，或删除符合条件的未开始任务；不能通过目标终态自动停止下属周期任务。

### 已解决分支：父子模型与当天撤销

父任务可迁移、子任务保留快照且不可迁移、进度计算获取、当天撤销使子任务失效，见 R07／R25–R27。父任务不保存进度值，不等于已经确定父任务不保存任何计数。

### 已解决分支：父任务两个周期计数的含义

当前周期数为当前第几期，完成周期数为 100% 完成的周期数量，见 R08／R28。早先的同义用法已被用户本次澄清取代，不再把完成周期数解释为周期序号。

### 已解决分支：完成周期数是否持久化

用户选择保存完成周期数，不采用每次查询重新聚合的方案，见 R29；不改变父任务不保存进度值、子任务保留快照的规则。

### 已解决分支：完成周期数的计入与回退

当前期按是否满足要求实时增减，每期最多贡献 1；有效完成数大于等于要求数即满足，包括下调为 4/3 的情况，见 R30／R31。计数更新不意味着提前进入下一期。

### 已解决分支：历史周期冻结与历史目标锁定

已结束周期结果固定，不因后续要求变更重算，见 R32；父任务迁移不能解除完成时原目标的终态锁定，见 R33。

### 已解决分支：每次行动奖励与整期奖励

每个有效子任务实时获得 1 点经验、计为 1 次行动，合法撤销时同步回退，父任务不重复计数；首期没有整期完成额外经验，见 R34／R35。旧周期奖励公式不进入本轮范围。

### 已解决分支：目标计奖行动与目标进度

每个有效子任务按完成时目标归属参与目标计奖，父任务及完成周期数不额外计奖；目标奖励公式不变，见 R36。目标总进度仅统计原有一次性任务，周期父任务单独展示本期进度，见 R37。目标任务数和今日进度分别按 R50、R44 独立确认；相关任务列表仍待讨论。

### 已解决分支：规划时区与单次录入信息

周期相关日期统一采用北京时间，首期不提供子任务备注，完成信息由系统记录，见 R38／R39。不增加题库、专用题目链接或附件功能；具体字段清单及记录入口仍需细化。

### 已解决分支：跨天提交与今日父任务展示

用户明确跨天新写请求先拦截，再由前端提示并刷新，不自动补交，旧成功请求只重放回执，见 R40。今日单独展示运行中父任务及本期进度、当前期数与完成周期数，满额后仍可见但不能继续记录，见 R41。

### 技术候选，尚未采纳

- 先前为解释下一期生效，介绍过“规则版本与生效日期”的可能方案。用户现已选择不允许修改周期类型、次数调整当期生效；不再为这两类修改引入下一期切换的需求，该方案也未被采纳为架构决定。
- 次数调整不改写历史完成明细，也不能为满足下调后的要求而删除真实完成。是否保留每次次数调整的历史、如何支持历史要求的聚合，须结合后续统计口径决定。
- 查询时重新聚合完成周期数的方案未采用。已选择保存计数、按当前期是否满足要求实时维护且冻结已结束周期；跨期刷新与完整性校验仍待设计，不能把当前期计数规则直接套用到全部历史周期。
- 现行代码只支持一次性任务，取消完成会把任务恢复为待完成，目标计奖行动按 taskId 去重。采用父子模型需要重新定义子任务撤销及统计投影；不能只加父子关联字段后直接继承全部现有逻辑。
- 未决定具体表、字段、接口、定时任务或迁移方案；不能从已确认的业务规则推断已选定某种物理存储方案。

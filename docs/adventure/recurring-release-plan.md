## 完整备份清单和恢复核验

生产备份至少覆盖全库schema、数据、函数/触发器、RLS/policies、表和函数ACL、索引/约束、schema owner/授权、角色/成员关系/必要globals、扩展及版本/外部依赖、真实迁移历史、数据库级设置。凭据只能在受保护配置/加密备份或运行时，不进入PR/日志；不能把JSON数据导出、前向migration源文件或本机合成history当作完整备份。

数据库部分可采用受控 `pg_dump -Fc`，globals用适用 `pg_dumpall --globals-only` 或托管平台明确支持的机制；受管理角色、扩展二进制/版本和托管内部schema需按真实平台能力验证，不用忽略restore错误来冒充通过。本票本机演练已证明代表库的数据库对象/数据/ACL等价恢复，**没有新cluster独立globals恢复、生产扩展/迁移history或生产备份证明**。

正式恢复演练要在全新隔离目标安装相同PG/扩展和所需globals后，用 `pg_restore --exit-on-error` 恢复完整数据库，保存所有退出码/警告并逐表、函数签名、FK/索引/RLS/ACL及任务/事件/父子/计数/XP/revision/回执hash对账。核对备份SHA、制品SHA和真实迁移历史；失败、跳过或未覆盖对象均不得通过门禁。只有代表库方法成功，不足以满足生产阶段1/2。

阶段5出现新周期事实后的回退尤其需要保护旧页面未知回执与新增奖励，不能直接恢复较早备份丢弃这些事实。先冻结全部写入并备份当前状态，再评估前向修复；若整体恢复，必须由主会话核对数据保全方案和针对具体恢复动作的用户授权。

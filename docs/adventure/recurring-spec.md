## 周期与次数

1. 周期内自由完成，每次实际行动单独记录，不预排具体执行日。首期周／月／季／年分别为 7 天、1／3／12 个月，不提供每日周期或复杂重复规则。
2. 指定开始日为原始锚点，包含开始当天，结束于下一期开始前一天。周三开始则周三至下周二；不按自然周／月／季切段。
3. 月末或闰日缺失时临时取目标月末，后续回到原始锚点：1/31→2 月末→3/31；2/29 年周期在平年取 2/28、闰年回 2/29。
4. 每期要求为正整数，至少 1。达到或超过要求不能新增；不允许超额、补记或预记。允许同一天多次真实完成。
5. 周期类型创建后固定；开始日只能设今天或未来，未开始可改，开始当天起固定，即使进度为 0 也不能修改。
6. 次数可调整，当期立即生效并持续用于以后各期，允许降到已有完成数以下，例如 4/5→4/3；保留全部事实、显示实际次数，进度条视觉可封顶但不能伪造为 3/3。
7. 每期从 0 开始，不结转、不暂停、不顺延；上一期真实完成保留。不保存父任务进度值，也不另存每期进度快照。

## 身份、快照与归属

- 周期父任务有稳定身份，承载规则、当前归属、生命周期和完成周期数；当前周期数表示第几期，可由固定锚点和权威规划日期取得。本期进度由生效子任务计算。
- 每次完成创建独立子任务身份，并关联父任务。子任务保留完成时父快照与自身信息，不能迁移，不能被后续父任务编辑改写。首期没有子任务备注输入、展示或事后编辑。
- 快照最低覆盖：父子身份、发生时名称与通用说明、周期类型及锚点、当期序号和起止日期、当时要求次数、实际完成时间／北京时间日期、完成时目标身份／名称与适用分类标签；不可把当前父任务／目标值回填为历史值。
- 未开始或运行中的父任务可编辑名称、说明、要求次数；可在进行中目标之间或与独立身份迁移。保持父身份、锚点、期数、本期累计连续；原子任务和计奖归属不迁移，新完成采用迁移后归属。
- 当天合法撤销只使具体子任务及其完成／奖励失效，保留原数据，不能恢复为待办或另行迁移。关联列表及数量只显示生效子任务；从子详情撤销后返回父详情，该条立即消失，最后一条撤销后显示 0 项空态。

## 生命周期与目标终态

- 未开始、运行中、已结束分别按服务端日期和生命周期决定。首期没有暂停／恢复、计划结束日或自动结束。
- 运行中可手动结束，立即停止新增并只读保留，不可恢复；已有有效完成／奖励保留，不额外发结束奖励。结束父任务后，子任务也不能再撤销。
- 仅未开始且未结束的周期任务可删除。开始当天起即使从未完成或全已撤销，也不能删除；不能以“没有生效子任务”绕过开始状态。
- 目标达成／结束前必须先处理全部未结束周期父任务，包括未开始和本期满额的任务。按能力结束、迁出或删除未开始任务，系统不自动停止它们。
- 子任务完成时所属目标进入终态后，子任务只读；父任务迁移不能解除该锁定。没有历史主线或 historical_lock 字段回归。

## 周期计数、奖励与统计

- 保存完成周期数。当前期生效次数大于等于当前要求即满足，每期最多贡献 1；从不满足变为满足加 1，合法撤销或上调要求使其不足时减 1，再次满足可恢复，不能反复累加。
- 已结束周期的满足结果冻结，之后改要求不重算历史贡献。跨期不丢掉上一期贡献，也不凭空为没有行动的期加数；无需逐期进度表来实现此规则。
- 每个生效子任务即时 +1 XP、+1 行动；合法撤销各回退 1，沿用事实与奖励同事务、失效不追加负数冲正的规则。父任务、完成周期数及整期满足不重复奖励，首期无整期额外 XP。
- 目标计奖 N 包括完成时归属该目标且仍生效的周期子任务及原有一次性行动；父任务和完成周期数不计。沿用 N>0 时 N×系数 1／2／3、N=0 时固定 1 的公式。迁移不挪走旧行动、不补记旧独立行动。
- 目标总进度只统计一次性任务；周期进度在父任务单列。目标任务数为当前归属的一次性任务（待完成及完成）＋未结束周期父任务，子任务不重复计数。例如任务数 3、一次性进度 1/2。
- 今日进度计入当天生效子任务，父任务和本期剩余要求不进入今日分母。所有汇总使用完整范围及事实，不按当前列表页计算。

## 日期展示和可靠性

- 全部规划日期及可撤销窗口由服务端 Asia/Shanghai 判断，不随设备／首页地区变化。服务端取得账户锁后捕获本次权威时间，避免锁等待跨日造成错误归期。
- 今天显示所有运行中父任务及本期信息；满额仍显示，禁用新增。历史只展示实际完成及结束条目，未来不展开运行中父任务的周期预测。
- 未开始父任务显示在开始日，可编辑／删除，改开始日后入口移动；已结束父任务只读显示在真实结束日；子任务始终按真实完成日显示，不随父任务结束移动。
- 父任务与日期明细沿用同一日期入口和搜索，没有独立管理视图或 A/B/C 切换。
- 点“记录一次”直接提交，提交期间禁用重复操作；成功复用一次性 PlanningToast，并回读服务端事实、进度和成长。误操作按当天撤销规则处理。
- 依赖规划日期的新周期写入若已跨天，必须拦截且无业务写入，前端提示并刷新权威日期、期数及能力，不能自动补交。已成功的旧请求先按原回执重放，不因跨天／跨期再执行。
- 沿用账户事务锁、expectedVersion、稳定 requestId、规范化摘要和成功回执；同请求重复／未知重试只执行一次，异摘要拒绝，冲突只回读并等待用户主动操作。每次真实完成有独立身份，不能按父任务 ID 把多次合法行动去重成一次。
- 父子、目标、事件、回执、列表及错误均按认证 owner 隔离，禁止前端写奖励／完成周期数或自行推断权限。RPC 只向既有服务通道授权，浏览器和普通角色不能直接改表或调用内部特权函数。

## 首期排除范围

不做每日周期、固定日期重复、暂停／恢复、计划结束日、复杂 RRULE、补记／预记、超额完成、子任务备注、周期类型变更、整期奖励、月视图、一次性任务拆成多日排期，也不恢复主线。#57／#58 保持待办，不能把这些旧票的规则带入本轮。

## 实施任务与工程结论

先定稿共享契约与持久化设计，再按同一契约实施后端与前端，最后集成验收；依赖和责任见 [实施记录](recurring-implementation.md)。接口／物理结构／当前期计数完整性属于实现设计，应由契约任务在改产品前明确并记录，而不是继续扩大产品范围。

工程约束：保持既有一次性数据、历史回执和奖励；新库安装与当前四表非空库增量升级必须等价。升级不重新导入演示数据、不重算旧奖励或改写旧快照。迁移必须具备事务边界和后置断言；长 SQL 执行前确认通道上限，不得让结构与函数处于不一致中间态。

所有前后端实施分支从同步后的基线或明确记录的共享契约提交开始，在独立 Orca 工作区开发。任务属于一个集成交付；为避免依赖生产提前上线，后端与前端可基于已评审的契约功能提交开发，最终汇入非生产集成分支，统一向 main 提 PR。此依赖策略记录在各票，不授权任何子任务提前合并 main 或部署。

## 交付分级与阶段门禁

分级：**需确认的变更**，涉及核心任务生命周期、奖励、持久化和公开接口。当前已获记录、拆票、本地实现与验证授权；不等于合并／生产迁移／发布授权。

1. 固定规格和原型，建立共享契约与设计记录。
2. 后端／前端实现和隔离验证，完成数据兼容、视觉／范围对照及独立双轴评审。
3. 准备可审查 PR、必需 CI、迁移前后验证和回退方案；核对用户对具体变更的验收及合并／发布授权。
4. 获授权后才执行生产阶段：核实传输上限、完整可恢复备份及回退点、生产迁移与兼容部署顺序，逐阶段验收。迁移与旧／新客户端不兼容时先定停流窗口和门禁。
5. 部署提交和生产只读验收一致后再关闭 Issue；未获授权、CI 未通过或生产验收未完成时保持开放，不使用自动关闭关键词代替验收。

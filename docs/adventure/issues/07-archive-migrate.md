## 要做的事

把进行中目标迁入另一主线或独立身份，或为可操作任务更换归属；页面立即反映新位置，过去完成和奖励保留原归属。

## 验收标准

- [ ] 进行中目标可在独立区与在用普通主线之间及跨在用主线迁移，保持目标身份、任务随行；不创建新主线或支线空壳。
- [ ] 保留聚焦并先验目的配额，满额由用户先调整，不挤掉其他目标或自动取消聚焦；成功落在目的同类组末尾，其他目标相对顺序不变。
- [ ] 可操作任务可跨目标迁移或与独立身份互转，保留 task 身份、当前有效安排及状态；普通主线不直接挂任务，不复活已结束任务。
- [ ] 后端提供候选及原因，最终提交重验当前／目的可操作状态、归属、配额和版本；失败、取消及并发竞争均无部分迁移。
- [ ] 完成／达成事件及其内嵌奖励的任务、主线、目标、内容和日期快照不改；任务迁出不带走历史计奖，迁入不补记旧行动。原归属终态锁定不能通过当前新归属绕过，不重复发奖。
- [ ] 浏览器演示两类迁移、聚焦满额失败、刷新保持新归属以及详情显示原历史；真实事务验证同 owner 约束、部分失败回滚及迁移并发。
- [ ] 本票不实现结束与误建删除；目标达成、结束后历史锁定的跨命令组合在最终票集中重验，单票可用受控历史事实验证锁定校验。
- [ ] 本票新增或修改的查询、预览及命令使用后端权威计算和校验；前端只负责输入、确认、提交、展示和重新查询，不自行计算业务结果或乐观修改事实。
- [ ] 命令携带 expectedVersion 和 requestId，事实、事件、账户汇总、版本及成功回执同事务；同 key 重试不重复执行，异命令拒绝，409 重读确认，结果未知保留原请求，已成功而查询失败只重试读取。
- [ ] 通过正式 HTTP 到隔离真实数据库验证本票业务及持久结果、失败回滚、账户隔离和必要并发；浏览器完成本票关键操作并刷新回读，不用旧单表、原型或模拟持久化证明本票通过。提供当前版本证据，按仓库要求先密钥扫描再完成相关检查。

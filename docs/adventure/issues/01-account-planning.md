## 验收标准

- [ ] 页面从空规划、1 级、0 经验开始，统一新建入口、名称与完成标准必填、归属手选且无默认值；新目标不自动聚焦或创建任务，取消不保存。
- [ ] 普通主线最多 5 条在用，仅通过目标承载任务；创建／改名主线和创建／编辑目标可从页面完成，空目标不自动达成，无支线、目标删除、草稿或多阶段入口。
- [ ] 按已确认五表方向建立当前切片所需约束、数据库事务及后端适配；账户首次读取安全初始化，独立目标首次创建时才按需建立并复用独立结构，页面不展示 inbox，不导入旧单表或演示数据，不清理已有验收数据。
- [ ] 固定页面查询、预览、命令封套的传输约定及本票具体端点、字段、错误、文本限额和事务预算，配套契约测试并供后续票扩展；预览无业务写入、不推进版本。查询返回规划日期、版本和能力，命令返回稳定回执及版本再由前端查询。
- [ ] 五表按账户隔离、同 owner 关联、浏览器直接访问禁止；真实数据库验证首次并发初始化、主线并发配额、成功回执重试、异命令同 key、版本冲突、中途失败回滚及身份隔离，不逐表独立 REST 散写。
- [ ] 完成桌面与 390px 手机的创建、编辑、取消、刷新回读和键盘路径；为本票未交付的操作返回明确不可用能力，不暴露旧周期／次日结算入口。聚焦、排序和任务进度由独立票交付，不列为本票阻塞。
- [ ] 本票新增或修改的查询、预览及命令使用后端权威计算和校验；前端只负责输入、确认、提交、展示和重新查询，不自行计算业务结果或乐观修改事实。
- [ ] 命令携带 expectedVersion 和 requestId，事实、事件、账户汇总、版本及成功回执同事务；同 key 重试不重复执行，异命令拒绝，409 重读确认，结果未知保留原请求，已成功而查询失败只重试读取。
- [ ] 通过正式 HTTP 到隔离真实数据库验证本票业务及持久结果、失败回滚、账户隔离和必要并发；浏览器完成本票关键操作并刷新回读，不用旧单表、原型或模拟持久化证明本票通过。提供当前版本证据，按仓库要求先密钥扫描再完成相关检查。

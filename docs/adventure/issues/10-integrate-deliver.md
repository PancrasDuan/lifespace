## 验收标准

- [ ] 逐项对应父规格 49 条故事及每票证据，覆盖迁移后达成计奖、迁出后原归属终态锁定、改期后误建删除资格、聚焦配额竞争、达成与取消竞争、结束后历史／进度及隐藏来源详情等跨票组合，发现缺口在本票修复并重新验证。
- [ ] 真实数据库重验五表权限、同 owner 关联、事务失败回滚、汇总等于有效奖励、旧已失效回执幂等、版本并发及跨午夜；区分受控身份与真实登录证据，不触碰未授权验收数据。
- [ ] 真实页面验证预览无业务写入、预览过期需重新确认、命令成功后查询失败仅重读、未知结果沿原请求重试、409 不自动重放、账户切换与倒序响应防覆盖。
- [ ] 桌面、390px 手机和键盘操作覆盖 A 行动工作台；基础成长反馈、七个成就、统一终态开关记忆、独立任务筛选及任务进度与后端一致，前端不计算业务结果。
- [ ] 旧单表写路径、周期入口、次日结算及浏览器重复业务计算不再参与本期功能；对没有调用者的旧实现作必要收敛，保留历史验证范围而不冒称新版通过，不删除旧数据库或数据。
- [ ] 密钥扫描先行，接口、安全、类型、构建、冒险与首页新闻浏览器回归通过；完成需求与规范双轴 review 并修复阻断问题，中文报告区分各类实际证据及剩余风险。
- [ ] 启动并保持功能分支本地预览，主动打开供用户验收；用户验收与具体 PR 合并授权分别取得，不预先授权合并。获准后核对部署 SHA 和生产隔离，再按仓库规则关闭相关 Issue；父规格不在本次拆票中修改或关闭。
- [ ] 本票新增或修改的查询、预览及命令使用后端权威计算和校验；前端只负责输入、确认、提交、展示和重新查询，不自行计算业务结果或乐观修改事实。
- [ ] 命令携带 expectedVersion 和 requestId，事实、事件、账户汇总、版本及成功回执同事务；同 key 重试不重复执行，异命令拒绝，409 重读确认，结果未知保留原请求，已成功而查询失败只重试读取。
- [ ] 通过正式 HTTP 到隔离真实数据库验证本票业务及持久结果、失败回滚、账户隔离和必要并发；浏览器完成本票关键操作并刷新回读，不用旧单表、原型或模拟持久化证明本票通过。提供当前版本证据，按仓库要求先密钥扫描再完成相关检查。

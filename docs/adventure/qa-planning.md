## 数据库状态与复跑

已应用迁移 `20261020130750_adventure_planning`。四个函数的去空白源码摘要与本地迁移一致；均为固定 `search_path` 的 `SECURITY INVOKER`。五表启用 RLS，浏览器角色无表和 RPC 权限，后端没有新增 DELETE 权限。新增对象的 RLS 无策略提示符合仅后端访问的设计，见 [提示说明](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)。

所有尝试共生成 14 个隔离测试账户；认证账户已删除，按精确 owner 白名单清理测试行后，Auth 和五表剩余数均回读为 0。未清理旧表或已有验收内容。

默认 CI 不注入业务配置，真实验收的六项 API 与两项浏览器用例会明确跳过。复跑需显式设置 `ADVENTURE_LIVE_TEST=1`，并通过受保护的进程环境提供 `ADVENTURE_TEST_URL`、`ADVENTURE_TEST_SECRET`、`ADVENTURE_TEST_PUBLISHABLE`；不得打印或提交值。测试自动删除自身创建的 Auth 用户，待按精确白名单清理的业务行 owner 写入忽略的 `.cache/adventure54-probe-owners.json`，不应授予应用额外 DELETE 权限来清理。

直连验收曾遇到 TLS 连接中断与认证 503；最终成功执行使用本机已配置的代理，仅设置测试进程的 `HTTP_PROXY`／`HTTPS_PROXY`／`NO_PROXY` 和 Node `--use-env-proxy`，未修改系统或应用代理配置。

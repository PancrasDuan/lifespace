## 实现范围

- A 行动工作台：普通主线创建／改名，主线内目标与独立目标创建／编辑／详情；取消不保存。新建入口统一在页面上方，目标卡片整卡进入详情。
- 目标归属默认独立、可清空，也可选择在用普通主线；后端负责落到独立目标。完成标准支持 1–50 个非空输入项，可逐项增删。
- 五表及账户隔离事务；按需建立唯一独立区与 inbox，页面隐藏系统结构。旧单表已由用户删除，本次迁移不重建或导入其数据。
- 页面查询、无写入预览及四种业务命令，具体字段和预算见 [接口契约](planning-api.md)。
- 稳定请求回执、版本冲突、原请求安全重试、成功后查询失败、倒序响应和账户生命周期保护。全局成功反馈使用浮动 toast。
- 本票未交付的任务、聚焦、排序、迁移、达成及结束入口明确禁用，不暴露旧周期或次日结算功能。

## 数据库状态与复跑

已应用迁移 `20261020130750_adventure_planning` 和 `20261021010000_adventure_goal_standards`。后者把现有单值 `standard` 转换为单元素 `standards` 数组，保留目标、主线、事件与版本，然后移除旧列并替换 RPC。四个函数均为固定 `search_path` 的 `SECURITY INVOKER`，浏览器角色无表和 RPC 权限，后端没有新增 DELETE 权限。新增对象的 RLS 无策略提示符合仅后端访问的设计，见 [提示说明](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)。

迁移前后回读用户验收账户：主线 `健康验收`、目标 `首次五公里验收`、标准 `在户外连续跑完五公里`、两条事件、`revision=2` 和 `total_xp=0` 均保留。迁移后页面刷新正常读取。

隔离验收共生成 24 个临时 Auth 用户；Auth 用户已删除。按精确 owner 白名单清理五表测试行时，云端连接一度中断，随后复核发现 10 个账户及关联测试行仍在；这些行只属于已删除的随机测试 owner，不影响验收账户，已列为待清理测试残留。

默认 CI 不注入业务配置，真实验收的六项 API 与两项浏览器用例会明确跳过。复跑需显式设置 `ADVENTURE_LIVE_TEST=1`，并通过受保护的进程环境提供 `ADVENTURE_TEST_URL`、`ADVENTURE_TEST_SECRET`、`ADVENTURE_TEST_PUBLISHABLE`；不得打印或提交值。测试自动删除自身创建的 Auth 用户，待按精确白名单清理的业务行 owner 写入忽略的 `.cache/adventure54-probe-owners.json`，不应授予应用额外 DELETE 权限来清理。

直连验收曾遇到 TLS 连接中断与认证 503；最终成功执行使用本机已配置的代理，仅设置测试进程的 `HTTP_PROXY`／`HTTPS_PROXY`／`NO_PROXY` 和 Node `--use-env-proxy`，未修改系统或应用代理配置。

# 人生冒险模块规格

状态：当前有效规格，对应 [父规格 #53](https://github.com/PancrasDuan/lifespace/issues/53)。功能分支已实现领域命令、持久接口与页面，验证范围及尚未证明的交付项以 [覆盖记录](coverage.md) 为准；不将本规格视作全部交付完成的声明。

## 问题陈述

想做的事情多，但缺少整体规划，看不到成长。使用者需要有限的长期主线、可聚焦的阶段结果与当天能执行的任务，并以经验、等级、成就回看投入和成果。

## 解决方案

在首页与新闻并列增加“人生冒险”正式页面，提供冒险概览、主线与支线、成长记录。以真实账户隔离持久保存容器、目标、行动与不可重复结算的成长账本；周期任务按任务月奖励长期坚持。本期默认采用A目标工作台作为正式组织，保留像素个人形象、紧凑经验条、右侧 dashboard 与成就横排。C 全站深绿夜间主题不在本期。

## 实施决策

- 领域结构：账户拥有主线／支线容器，目标属于一个容器，任务或周期规则属于目标；行动实例与行动身份分别保存，重新安排保留同一行动去重身份。周期额外真实活动使用新的行动身份。历史以稳定来源编号和不可变快照可追溯。
- 配额、聚焦、归属、只读、日期冻结、目标去向及去重规则全部由服务端验证；不能只靠 UI 禁用或客户端总量。
- Worker 复用在线验证的当前用户身份，owner 不从请求体信任；每次读写均限制当前账户。既有首页共享任务来源不迁入、不改写、不扩大浏览器数据库权限。
- 持久化复用现有 Supabase 独立 adventure_states，以 owner_id 为主键、state jsonb 保存个人领域状态、version bigint 作为版本，journal与领域状态同次提交。Worker 严格执行命令校验，服务端生成新状态，再以 owner_id 与 version 条件通过 PostgREST PATCH CAS 原子提交；初始化 ignore-duplicates；普通命令版本冲突返回 409，刷新结算可有限重算。禁止客户端整包 state 写入，不引入 RPC 全套关系表，不退回 localStorage 或内存伪持久化。
- 所有改变成长的命令通过同一服务端领域命令边界，服务端权威日期、每账户完整状态的原子 CAS 提交、稳定结算键和幂等命令键避免重复请求、并发标签页与进程重试双发奖。配额和聚焦也在同一 CAS 前重新校验。所有编辑、规则、排序、普通创建和其他用户变更命令携带 expectedVersion，版本不匹配返回 409，提示刷新重新确认，不能自动把旧视图意图覆盖新状态。只有刷新结算可在 CAS 冲突后有限次数重读、重算。数据库操作失败不提交任何部分状态。
- 幂等 journal 与领域状态在同一 owner CAS 原子提交：以 owner＋requestId 标识命令，保存 payload 摘要和稳定 command 结果。同 key 异 payload 拒绝；结果未知时客户端保留原 key 重试，不产生第二次动作或奖励。重复命令返回最新 state 和稳定 command 结果，不返回旧快照覆盖当前客户端状态。客户端按 version 接受新状态，防止并发响应倒序回写。
- 持久表只允许 Worker service_role 访问；anon 与 authenticated 对表的直接读取、插入、修改和删除均拒绝，service_role仅授予SELECT／INSERT／UPDATE，不授予DELETE。迁移版本20261019035109及真实权限探针已验证，详见后端验证；Worker路由测试不能替代数据库权限。
- API契约：GET `/api/adventure`只读取／初始化缺失账户，不结算；页面读回后POST `/api/adventure/commands`发送`refresh`，以服务端日期惰性追赶昨天及更早记录。无后台定时器或客户端模拟日期。
- 时间默认固定账户规划时区 Asia/Shanghai；服务端取当日，不信任客户端演示日期；不随天气地区变动改写历史。日期区间默认 [任务月起点, 下一满月日)，满月日到期，下一日可结算。该规划时区不修改首页现有地区时区语义。
- 每次完整候选持久行（含state、journal、owner、version、updated_at）按UTF-8限制8,000,000 bytes；超限写入前拒绝、旧行继续可读，不裁剪幂等或历史。这是有限容量，不承诺无限历史；真实Worker接近预算的内存峰值仍需验证。
- 周期规则按生效日期版本化，过去冻结；按所有有效规则区间与暂停区间算计划，不能仅用浏览器已生成 28 天实例数。排期提供滚动查询／生成及遗漏月份追赶，确保任意未来时间或长时间离线仍正确。周期结束日期包含当天；完整月到期日以前结束则不发该残月周期奖励。
- 周期单实例改期保留原计划槽位、slot ID 和计划所属任务月，实际完成计入执行日期所属任务月。跨月改期不移动或重写原分母，不重新生成原槽位；同一 action 只有一次单次奖，额外完成没有计划槽位。未选择“随执行日移动分母”，因为会造成计划责任丢失及历史分母漂移。
- 周期奖励：P=0 时 R 不适用、奖励零、不增达标月；P>0 时 R=min(A/P,1)，本期前累计达标月 Q，K=1.1^floor(Q/3)，本期 R≥0.8 才应用 K。奖励 floor(10×R×适用K)，先计算再向下取整；每满月最多 Q+1。使用整数／有理精度保证 10×1.21 得到 12，不能因二进制浮点误差少发。
- 次日结算按历史日期顺序处理昨天及更早的未结算单次、目标和已到期完整任务月，再更新等级与成就；当前日不结算。每笔来源有独立唯一键。周期奖励不增加行动数；目标奖励只增加达成目标数；单次才增加行动次数。
- 目标奖励冻结于确认达成时的真实独立行动数和系数，包括此前完成但未结算的合法记录；检查清单不计次数。后续继续活动不进入原目标冻结计数。确认目标后，若要撤销计入冻结奖励的当天任务，须先撤销当天目标达成；避免冻结奖励与行动数矛盾。撤销目标只撤目标待结算并恢复确认前周期 running／paused／ended 状态与去向选择，不撤任务完成；不能强制恢复暂停、重复生成安排或丢弃确认后动作，需校验并保留动作历史。
- 暂停之前已到期的完整任务月必须先处理或保留可结算，暂停不能阻挡其结算。归档与达成分别建模：归档不发目标奖，停止未完成安排、取消聚焦、只读保留来源；历史待结算仍可结算。达成后继续的周期任务可在全部任务及周期管理操作，但不重开原目标或改变冻结奖励。
- 已达成但未归档的支线仍允许升级为新主线或迁入已有主线，保留同一目标、任务、周期和冻结奖励，不重算历史；归档仍只读、禁止迁移。暂停周期允许撤销当天未结算完成以纠错，但不得追加完成或执行清单；结束与归档仍只读。
- 初始正式账户从 0 XP、Lv.1、无虚构历史开始。原型 72 XP、48 行动与模拟任务不自动导入；若需要历史导入须另有真实来源，缺失内容明确标注。
- UI 状态具有服务端读回依据；首次空白、加载、错误、安全重试、无匹配任务与配额满状态均可理解。弹窗可用 Escape 关闭并保持焦点，关闭回原目标；移动端布局和键盘排序与桌面相同规则。
- 演示工具、独立推演及 A/B/C 切换属于原型，不把模拟日期或任意初始数据入口暴露给正式写接口；原型保持独立隔离。

## 测试决策

优先一个领域命令边界覆盖业务状态及存储结果，有限补充真实 Worker HTTP 账户隔离与浏览器端到端路径。测试观察输出、持久状态、账本和页面行为，不锁死私有函数或组件树。

- 命令测试覆盖主线 5／支线 10／聚焦 3 并发限制、迁移原子性、归档、当天撤销、重新安排同一行动、额外完成、规则版本、排序不影响聚焦。
- 奖励测试覆盖三类同批结算、请求并发与重试、断点恢复、多月追赶、无计划、超额、79%／80%、整数下取、3/6 月边界、1/31→2/28→3/31、闰年、跨年、重复暂停与恢复、残月结束、午夜跨日。
- 幂等与版本测试覆盖同 key 同 payload 重试、异 payload 拒绝、未知结果恢复、并发命令仅一个旧版本成功、409 不悄悄覆盖、返回最新 state 与稳定 command 结果，以及客户端倒序响应。真实数据库探针验证 anon／authenticated 直读直写删除拒绝。
- HTTP 测试同时使用两个有效真实风格身份和无效身份，尝试跨账户猜 ID 读取、变更、排序、迁移与结算；服务端日期不可客户端篡改，错误响应无凭据。
- 浏览器验证统一创建占位、编辑取消、上下文返回、目标排序、任务安排／重新安排／额外完成、周期去向、统计与账本一致、跨刷新持久、并发二标签页同源、窄屏及键盘。
- 现有先例是 Worker HTTP API 的 Vitest 测试、认证夹具和 Playwright 页面回归；复用 Auth HTTP 边界夹具，不模拟掉人生冒险自身事务逻辑。持久层需证明真实 owner＋version 条件 PATCH／CAS 冲突与 ignore-duplicates 初始化语义，不仅用无版本检查的假仓库单测。
- 交付跑密钥扫描、接口与安全测试、类型检查、构建、浏览器回归；gpt-6-astra 做需求与规范双轴 review；本地浏览器给用户验收，取得具体 PR 合并确认后合并，核验 Cloudflare 对应 SHA 发布和生产账户隔离。

# 后端设计约定

状态：2026-10-20 数据库与业务逻辑设计稿，暂不实现；既有代码和测试不证明本版通过。数据库字段及内部版本属于设计选择，HTTP 契约留到接口定义阶段。

- [数据库设计](backend-database.md)：现有物理表、六类逻辑记录、字段与关联、逻辑删除、幂等、容量和 schemaVersion=2。
- [业务逻辑](backend-business-logic.md)：后端 Module 职责、命令处理、完成／取消、计奖、终态、迁移、读取能力与设计验收。
- [前端设计](decisions-frontend.md)：A 工作台及接口需提供的能力；[成长与奖励](growth-rewards.md)：已确认的计算规则。

| 事项 | 本期设计 |
|---|---|
| 存储 | 沿用 adventure_states 单账户聚合及 PostgREST Adapter，不新增物理业务表或关系表事务 RPC。 |
| 物理约束 | owner_id 主键、JSONB 根对象、非负安全整数 version；JSON 内关联及业务唯一性由后端校验，不能冒称 SQL 外键或唯一索引。 |
| 权限 | RLS 开启，无浏览器直接表权限；service_role 仅 SELECT／INSERT／UPDATE，沿用无 auth.users 外键。每次在线验证 owner 并强制 owner 条件。 |
| 任务身份 | 一次性 taskId 始终稳定，执行安排为独立不可变历史；完成和对应奖励有各自 ID，取消具体完成，旧请求不影响新完成。 |
| 原子性 | 事实、奖励、journal、version 同次 CAS；普通命令冲突不自动重放，未知结果沿用原请求安全重试。 |
| 幂等 | 同 owner／requestId 同命令只应用一次，摘要不包含 expectedVersion；journal 保留稳定事实回执，不保存等级或成就状态。 |
| 读取与预览 | 后端生成能力、原因、候选、影响和实时成长，最终提交重新校验；读取刷新不补发奖励或写业务 journal，空账户初始化例外。 |
| 时区 | 服务端确定 Asia/Shanghai 规划日期；客户端不指定 owner、经验、today 或整包 state。 |
| 容量 | 完整候选行紧凑 UTF-8 预算 8,000,000 bytes，上游读取 32 MB，单次上游请求 10 秒；超限拒绝、不裁剪。真实 Worker 接近预算时的峰值仍需实现验收。 |
| 请求限制 | 沿用 JSON 命令 128 KiB、5 秒读取限制；原始外部错误脱敏，不把凭据或完整个人内容写入日志。 |
| 版本 | 当前旧代码内部版本为 1，本设计为 2；未支持结构明确拒绝，不自动覆盖或清空，不在本次转换验收数据。 |

本轮没有读取真实账户内容、连接业务数据库、执行 SQL、生成迁移或调整权限，也不新增依赖、修改正式实现或发布远端 Issue。已有数据库与持久化证据仍保留在 [后端验证](qa-backend.md)，仅代表其注明的旧版范围。

- [数据库设计](backend-database.md)：五张真实表、PostgreSQL 类型、外键、索引、事件与样例。
- [业务逻辑](backend-business-logic.md)：事务、完成／取消、目标奖励、迁移、终态、能力与验收。
- [前端设计](decisions-frontend.md)、[成长与奖励](growth-rewards.md)：已确认的消费和计算规则。

| 事项 | 本期设计 |
|---|---|
| 物理表 | accounts、mainlines、goals、tasks、events 五张 public.adventure_ 表；不建安排、完成、奖励或回执分表。 |
| 账户汇总 | accounts.total_xp 保存当前有效奖励之和，事务维护并与有效完成／达成事件冻结 amount核对；等级、成就实时计算。 |
| 独立结构 | 首次独立目标或任务按需创建并复用独立主线；独立任务引用唯一 inbox 目标。inbox 不展示、不聚焦、不达成、不计目标奖励／成就。 |
| 任务 | tasks 只保存当前 planned_on 和当前状态；改期原日期、归属、完成及历史在 events。task id 稳定，改期不换行动。 |
| 事件 | events 保存操作历史、完成、取消、奖励、计奖依据、快照和成功回执；幂等查询包含已失效事件。 |
| 奖励 | 奖励直接冻结于 task_completed／goal_achieved；取消只失效指定完成及其内嵌奖励，不撤销目标奖励，不追加负数冲正。 |
| 事务 | Worker → Supabase PostgREST → PostgreSQL SECURITY INVOKER RPC，单次调用完成事务，锁 accounts 后校验 revision、事实、total_xp 和回执；不能逐表 REST 散写。 |
| 并发 | 保留账户级 expectedVersion；同账户不同任务仍可能冲突，五表不等于按任务独立并发。 |
| 接口分工 | 页面查询返回后端投影，预览无业务写入，命令成功后只返回回执及版本并由前端重新查询；查询失败不重做已成功命令。 |
| 读取 | 短事务账户共享锁保证当前对象、revision、事件汇总和成长一致；内部可写 POST RPC，不用 READ ONLY GET。 |
| 权限 | 五表启用 RLS，无浏览器直接权限；后端角色最小 SELECT／INSERT／UPDATE，无物理 DELETE，事务函数仅后端可执行。 |
| 容量 | 取消整账户 JSON 8 MB 依赖；分记录长度、分页、返回量和事务预算，超限整笔拒绝，不裁剪事件或回执。 |
| 任务规则 | 逾期、今天及未来任务均可在今天完成，实际完成时间与日期取服务端操作时间，计划日期保留；取消窗口按实际完成日，跨日冻结；四字段统一编辑；未完成任务可逻辑删除；终态前必须处理待办。独立改期／迁移／结束任务不接受新命令，历史成功回执仍可重放。 |

#185 在当前四表模型上放开未来完成限制，日期写入、独立日期列表、奖励与取消流程保留；旧页面的今天任务与汇总排除实际在之前完成的任务，避免原计划日到来时重复计数。空库继续加载 create-planning.sql 与 list-tasks.sql；现有目标分类库先完成 ADR 0011 的清理，再应用 `20261114020502_adventure_future_completion.sql`。该迁移单事务替换任务校验、能力、预览和页面读取四个函数，重申仅 service_role 执行权限并刷新 schema，不修改业务行。
| 实施 | 空库依次加载 create-planning.sql 与 list-tasks.sql；已有五表库使用 20261106200055_adventure_today_task_rules.sql，同一事务替换规则函数、补充日期列表索引／RPC及权限并刷新schema，不修改业务行。本轮不执行生产升级或数据清理。 |

主要业务验收边界为正式 HTTP 接口到真实数据库事务，提交后重新读取并验证事实、奖励、版本、回执及持久化；隔离数据库覆盖事务回滚、外键、权限和并发，不以模拟成功代替。浏览器覆盖关键流程、刷新和手机布局；计算测试仅补必要临界值。

原关系表决策已更新为当前 [五表决策](../adr/0002-adventure-owner-state.md)；旧验证仅保留其历史范围。
